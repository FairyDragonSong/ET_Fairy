## 三、YooAsset 改为项目内嵌包

### 3.1 原问题

团结引擎打开项目时无法访问：

```text
package.openupm.com
```

原项目通过 OpenUPM 获取 YooAsset，团结环境中该依赖不稳定。

### 3.2 处理方式

将 YooAsset 2.1.1 放入：

```text
Unity/Packages/com.tuyoogame.yooasset
```

`Unity/Packages/manifest.json` 改为：

```json
"com.tuyoogame.yooasset": "file:com.tuyoogame.yooasset"
```

同时：

- 移除了 `package.openupm.com` 的 scoped registry。
- `packages-lock.json` 中 YooAsset 的来源改为 `embedded`。
- 删除了本机 OpenUPM Package Cache：

```text
C:\Users\song\AppData\Local\Unity\cache\packages\package.openupm.com
```

项目现在不再依赖 OpenUPM 获取 YooAsset。

## 四、旧版 DOTween 与 UnityEngine 兼容程序集

### 4.1 报错

旧版 DOTween/DOTween Pro 在团结编译环境中出现：

```text
The type 'Component' is defined in an assembly that is not referenced.
You must add a reference to assembly 'UnityEngine'
```

类似报错还包括：

```text
Material
Vector3
```

### 4.2 原因

`Component`、`Material`、`Vector3` 的真实实现位于：

```text
UnityEngine.CoreModule.dll
```

但旧版 DOTween DLL 编译时记录的依赖程序集身份仍然是：

```text
UnityEngine.dll
```

团结和 Unity 提供的 `UnityEngine.dll` 是兼容门面程序集，通过类型转发把旧程序集引用转到各个模块程序集。类型并没有在两个 DLL 中重复实现。

### 4.3 当前处理

新增：

```text
Unity/Assets/csc.rsp
```

内容：

```text
-r:"D:/Program Files/TuanJieEdit/2022.3.62t11/Editor/Data/Managed/UnityEngine/UnityEngine.dll"
```

这让 C# 编译器显式引用团结提供的兼容门面程序集，解决旧 DLL 的程序集身份依赖。

该引用会参与 Player 脚本编译，但不会把编辑器 DLL原样打进最终包；最终类型仍由团结 Player 对应的模块程序集和 IL2CPP 提供。

升级 DOTween Pro 并不能保证解决该问题，因为较新的官方 DOTween DLL 仍可能引用旧的 `UnityEngine` 程序集身份。

## 五、Process.WaitForExitAsync 兼容问题

### 5.1 报错

```text
'Process' does not contain a definition for 'WaitForExitAsync'
```

### 5.2 原因

当前团结目标使用的 .NET API 集合没有提供：

```csharp
System.Diagnostics.Process.WaitForExitAsync()
```

项目已经定义了兼容扩展方法，但原条件编译使用了项目自定义的：

```csharp
#if UNITY
```

团结微信小游戏并不定义该宏。团结会定义：

```text
UNITY_5_3_OR_NEWER
UNITY_WEIXINMINIGAME
TUANJIE_WEIXINMINIGAME
```

因此条件已调整为：

```csharp
#if UNITY_5_3_OR_NEWER
```

### 5.3 当前仍待修复

`Unity/Assets/Scripts/Core/Helper/ProcessHelper.cs` 中仍存在一个条件写反的问题：

```csharp
if (!self.HasExited)
{
    return;
}
```

这会在进程仍运行时直接返回。应改成：

```csharp
if (self.HasExited)
{
    return;
}
```

在修复前，调用方虽然能够通过编译，但 `waitExit` 的等待语义不可靠。

## 六、微信小游戏色彩空间与图形 API

### 6.1 报错

```text
Error building Player: Incompatible color space with graphics API: 8
```

### 6.2 原因

项目使用 Linear 色彩空间：

```yaml
m_ActiveColorSpace: 1
```

原微信配置使用 WebGL 1/OpenGLES2，对应图形 API 枚举值 8。OpenGLES2 与当前 Linear 配置不兼容。

### 6.3 处理

保持 Linear 色彩空间，启用微信小游戏 WebGL 2.0：

```yaml
Webgl2: 1
```

当前生效配置位于：

```text
Unity/Assets/WX-WASM-SDK-V2/Editor/MiniGameConfig.asset
```

注意：

```text
Unity/Assets/Settings/Build Profiles/New WeChat Profile.asset
```

中仍保留了 `Webgl2: 0`，但该 Build Profile 当前没有启用。后续如果改用该 Profile，需要同步改为 WebGL 2.0。

## 七、看似重复导入，实际是 Burst 重编译循环

### 7.1 现象

编辑器长时间反复刷新，表面上像某个资源在重复导入。

日志实际显示：

```text
Imports: total=0
new=0, changed=0, moved=0, deleted=0
```

但同时多次出现：

```text
Burst was previously disabled and is now enabled; recompiling scripts
Requested script compilation because: Requested through public api
```

### 7.2 原因

当时使用的团结 Burst `1.8.30-t1` 在微信小游戏目标下没有生成 BurstLoader 预期的：

```text
$BurstDirectCallInitializer
```

每次 Domain Reload 后，BurstLoader 都重新请求 Clean Build，形成：

```text
脚本编译
→ Domain Reload
→ Burst 再次请求脚本编译
→ Domain Reload
```

这不是资源重复导入，也不应该通过删除图片、Prefab 或 YooAsset 资源处理。

### 7.3 当前状态

当前 Package 已更新为：

```json
"com.unity.burst": "1.8.30-t2"
```

空场景已经能够完成微信小游戏导出。若以后再次出现类似长时间刷新，应先检查 Editor.log 中的 Burst 重编译信息，而不是直接删除资源。

临时诊断时，可以为单次编辑器启动禁用 Burst：

```powershell
$env:UNITY_BURST_DISABLE_COMPILATION='1'
& 'D:\Program Files\TuanJieEdit\2022.3.62t11\Editor\Tuanjie.exe' `
  -projectPath 'E:\github\ET\YIUI\Unity'
```

这只能作为诊断或临时绕过手段，不能默认作为正式包配置。

## 八、F6 编译时 MongoDB.Driver 缺失

### 8.1 报错

```text
DBComponent.cs(1,15): error CS0234:
The type or namespace name 'Driver' does not exist in the namespace 'MongoDB'
```

### 8.2 原因

`MongoDB.Driver.dll` 存在，但其 PluginImporter 只允许：

```text
Editor
Standalone
```

不允许微信小游戏平台。

当 `GlobalConfig.CodeMode` 为 `ClientServer` 时，F6 会把：

```text
Assets/Scripts/Model/Server
```

一起编入微信小游戏 Player，其中 `DBComponent.cs` 依赖 MongoDB，于是编译失败。

### 8.3 处理

微信小游戏必须使用：

```yaml
CodeMode: 1
```

即：

```text
CodeMode.Client
```

F6 会通过 `AssemblyTool` 生成 `Model/Server/Ignore.asmdef`，把服务端代码排除在客户端编译之外。

不要把 MongoDB DLL 强行启用到微信小游戏：

- MongoDB 是服务端依赖。
- 小游戏客户端不能直接访问数据库。
- 数据库地址和凭据也不应该进入客户端包。

## 九、HybridCLR 升级与团结专用分支

### 9.1 原问题

原项目使用：

```text
HybridCLR 4.0.15
hybridclr native v4.0.10
il2cpp_plus v2022-4.0.8
```

该版本不会识别团结引擎的 `t` 版本后缀，会错误选择普通 Unity 2022 原生分支。

由此出现两类 C++ 接口不匹配：

```text
IL2CPP_POP_ACTIVE_EXCEPTION(Exception_t*)
```

与旧头文件中的：

```text
IL2CPP_POP_ACTIVE_EXCEPTION()
```

以及三参数：

```text
il2cpp_codegen_get_marshal_directive_exception(...)
```

与旧头文件中仅有的一参数版本不匹配。

### 9.2 处理

`Unity/Packages/manifest.json` 已锁定：

```json
"com.code-philosophy.hybridclr":
  "https://gitee.com/focus-creative-games/hybridclr_unity.git#v8.12.0"
```

`packages-lock.json` 锁定官方提交：

```text
e4def761d69b27b7b51a5de0f6d272861416a2d6
```

新版 Installer 能识别团结引擎，并选择：

```text
hybridclr: v8.12.0
il2cpp_plus: v2022-tuanjie-8.11.0
```

执行了：

```text
HybridCLR → Installer
```

生成的：

```text
HybridCLRData/LocalIl2CppData-WindowsEditor/
  il2cpp/libil2cpp/hybridclr/generated/UnityVersion.h
```

已经包含：

```c
#define HYBRIDCLR_UNITY_VERSION 20220362
#define HYBRIDCLR_TUANJIE_VERSION 10903
```

说明 Installer 已正确识别：

- Unity 兼容版本：2022.3.62
- 团结运行时版本：1.9.3

### 9.3 版本风险

HybridCLR 官方公开更新记录当前明确写到合并团结 1.6.8，而本项目使用团结 1.9.3。

`v8.12.0` 是当前公开版本中最合适的选择，并已解决最初的 IL2CPP 接口错误，但正式发布前仍需完整验证：

- AOT 元数据加载。
- 热更新程序集加载。
- 泛型桥接。
- 真机异常和崩溃。
- 微信小游戏文件系统与远程下载。

## 十、HybridCLR 与 Slim Global Metadata

### 10.1 报错

执行：

```text
HybridCLR → Generate → All
```

时出现：

```text
hybridclr doesn't support 'SLIM_GLOBAL_METADATA_FILE == 1'
```

并伴随：

```text
vector<int32_t>
vector<uint16_t>
```

类型不匹配。

### 10.2 原因

团结微信小游戏提供：

```text
Use Slim Format For global-metadata.dat
```

开启后：

```text
SLIM_GLOBAL_METADATA_FILE=1
```

团结会将部分元数据索引从 `int32_t` 压缩成 `uint16_t`，并改变 `global-metadata.dat` 的结构。

HybridCLR 8.12.0 明确不支持该精简格式，因此主动用 `#error` 阻止构建。后面的 `vector` 类型错误也是 Slim 模式造成的连锁错误。

### 10.3 处理

在：

```text
Project Settings
→ Player
→ WeixinMiniGame
→ Publishing Settings
```

关闭：

```text
Use Slim Format For global-metadata.dat
```

当前配置已经是：

```yaml
weixinMiniGameUseSlimMetaFileFormat: 0
```

关闭后 `HybridCLR → Generate → All` 能继续完成。代价是 `global-metadata.dat` 会略大，这是当前使用 HybridCLR 必须接受的。

不要直接删除 HybridCLR 中的 `#error`。即使强行越过编译，运行时仍会按照错误的元数据布局读取数据。

## 十二、下一阶段：接入 Init 场景

### 12.1 当前状态

`EditorBuildSettings.asset` 当前为：

```text
Assets/Scenes/Init.unity       enabled: 0
Assets/Scenes/MiniGame.scene  enabled: 1
```

`GlobalConfig.asset` 当前为：

```yaml
CodeMode: 1
EnableDll: 1
BuildType: 1
AppType: 7
EPlayMode: 0
```

其中：

- `CodeMode: 1` 是正确的客户端模式。
- `EnableDll: 1` 表示使用热更新 DLL。
- `EPlayMode: 0` 是 `EditorSimulateMode`，不能用于小游戏 Player。

### 12.2 微信小游戏需要 WebPlayMode

YooAsset 2.1.1 的枚举值为：

```text
EditorSimulateMode = 0
OfflinePlayMode    = 1
HostPlayMode       = 2
WebPlayMode        = 3
```

微信小游戏同时属于 WebGL 运行环境。YooAsset 会明确拒绝在 WebGL Player 中使用 Offline 或 Host：

```text
OfflinePlayMode can not support WebGL plateform
HostPlayMode can not support WebGL plateform
Please use WebPlayMode
```

因此正式加入 `Init` 场景前，需要把：

```yaml
EPlayMode: 0
```

改为：

```yaml
EPlayMode: 3
```

### 12.3 ResourcesComponent 尚缺 WebPlayMode 分支

当前：

```text
Unity/Assets/Scripts/Loader/Resource/ResourcesComponent.cs
```

只处理：

- `EditorSimulateMode`
- `OfflinePlayMode`
- `HostPlayMode`

如果只修改 GlobalConfig 为 `WebPlayMode`，代码会进入：

```csharp
default:
    throw new ArgumentOutOfRangeException();
```

需要增加：

```csharp
case EPlayMode.WebPlayMode:
{
    string defaultHostServer = GetHostServerURL();
    string fallbackHostServer = GetHostServerURL();

    WebPlayModeParameters createParameters = new();
    createParameters.BuildinQueryServices = new GameQueryServices();
    createParameters.RemoteServices =
        new RemoteServices(defaultHostServer, fallbackHostServer);

    await package.InitializeAsync(createParameters).Task;
    break;
}
```

### 12.4 远端地址不能继续使用 localhost

当前 `GetHostServerURL()` 返回：

```text
http://127.0.0.1/CDN/WebGL/v1.0
```

在手机或微信开发者工具中，`127.0.0.1` 指运行小游戏的设备本身，不是开发电脑。

后续方案：

- 全量内置测试：把启动所需 YooAsset 文件全部放进 StreamingAssets，确保启动阶段不访问远端。
- 局域网测试：使用电脑局域网 IP，但需要处理微信网络安全限制。
- 正式环境：使用 HTTPS CDN，并在微信公众平台配置合法域名。

## 十三、推荐构建顺序

涉及业务代码、热更新 DLL 或 AOT 引用变化时，建议使用以下顺序：

```text
1. GlobalConfig 设置为 Client + WebPlayMode
2. F6
3. HybridCLR → Generate → All
4. HybridCLR → CopyAotDlls
5. YooAsset ForceRebuild
6. 确认 Init 场景位于 Build Settings 第一项
7. 微信小游戏转换
8. 微信开发者工具运行验证
```

仅修改场景内容、且没有修改热更新代码和 AOT 引用时，可以根据实际变更缩短流程，但正式出包前建议完整执行一次。

## 十四、当前结论

本次迁移已经完成“团结引擎打开项目 → 解决 Package 和编译兼容 → 配置微信小游戏 → 适配 HybridCLR → 空场景成功运行”的第一阶段。

下一阶段的核心不再是团结基础构建，而是 ET 业务启动链：

```text
Init 场景
→ YooAsset WebPlayMode 初始化
→ 读取内置资源清单

```

接下来遇到问题时，应优先根据这条链路定位“卡在哪一层”，避免把资源、HybridCLR、网络和业务代码错误混在一起处理。
