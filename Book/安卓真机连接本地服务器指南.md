# 安卓真机连接本地服务器指南

本文记录 YIUI/ET 项目在 Windows 本机启动服务端，并让同一局域网内的 Android 真机连接该服务端的完整流程。

## 一、网络关系

Android 真机中的 `127.0.0.1` 和 `localhost` 指向手机自身，不会指向开发电脑。因此，APK 必须连接电脑的局域网 IPv4 地址。

本文示例环境：

```text
电脑 WLAN IPv4：192.168.1.7
RouterManager：TCP 30300
Router：UDP 30301～30304
```

电脑切换 Wi-Fi、重启路由器或重新获取 DHCP 地址后，局域网 IP 可能变化。每次测试前可执行：

```powershell
ipconfig
```

找到 WLAN 适配器的 IPv4 地址。手机与电脑必须连接同一个 Wi-Fi，并确认路由器没有开启 AP 隔离、访客网络隔离等功能。

## 二、修改客户端连接地址

修改：

```text
Unity/Assets/Scripts/Hotfix/Share/ConstValue.cs
```

将 RouterManager 地址设置为电脑的局域网 IP：

```csharp
public const string RouterHttpHost = "192.168.1.7";
public const int RouterHttpPort = 30300;
```

修改后需要重新编译客户端热更新代码、重新构建资源，并重新安装 APK。只修改源码而不更新 APK 或热更新资源，手机仍可能使用旧地址。

## 三、修改服务端对外地址

修改配置源文件：

```text
Unity/Assets/Config/Excel/StartConfig/Localhost/StartMachineConfig.xlsx
```

配置为：

```text
InnerIP = 127.0.0.1
OuterIP = 192.168.1.7
```

含义：

- `InnerIP` 用于本机服务之间通信，保持 `127.0.0.1`。
- `OuterIP` 会作为 Router 的可访问地址返回给客户端，必须使用手机能够访问的电脑局域网 IP。

修改 Excel 后，重新生成 Luban 配置：

```powershell
Set-Location "E:\github\ET\YIUI\Tools\Luban"
.\GenConfig.bat
```

生成结果可在下面的 JSON 中核对：

```text
Config/Json/s/StartConfig/Localhost/StartMachineConfigCategory.json
```

其中应当包含：

```json
{
  "InnerIP": "127.0.0.1",
  "OuterIP": "192.168.1.7"
}
```

完成后重启服务端，使其重新读取生成的 `.bytes` 配置。

## 四、允许 Android 使用明文 HTTP

客户端会访问：

```text
http://192.168.1.7:30300/get_router
```

这是明文 HTTP。Unity 中设置：

```text
Edit
→ Project Settings
→ Player
→ Android
→ Other Settings
→ Configuration
→ Allow downloads over HTTP
→ Always Allowed
```

对应项目设置中的 `insecureHttpOption` 应为允许状态。修改后需要重新构建 APK。

> 注意：`Always Allowed` 仅适合本地开发和局域网测试。正式发布前必须先将 RouterManager 部署为 HTTPS，再关闭明文 HTTP。不能只关闭该选项而继续使用 `http://` 地址，否则客户端会在登录前获取路由列表时失败。

## 五、配置 Windows 防火墙

### 5.1 将可信任的测试 Wi-Fi 设置为专用网络

先以管理员身份打开 PowerShell：

```text
Win + X → 终端（管理员）
```

仅当当前 Wi-Fi 是可信任的家庭或测试网络时执行：

```powershell
Set-NetConnectionProfile -InterfaceAlias "WLAN" -NetworkCategory Private
```

检查结果：

```powershell
Get-NetConnectionProfile
```

### 5.2 放行 RouterManager TCP 30300

```powershell
New-NetFirewallRule `
  -DisplayName "YIUI RouterManager TCP 30300" `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 30300 `
  -Profile Private `
  -RemoteAddress LocalSubnet
```

### 5.3 放行 Router UDP 30301～30304

```powershell
New-NetFirewallRule `
  -DisplayName "YIUI Router UDP 30301-30304" `
  -Direction Inbound `
  -Action Allow `
  -Protocol UDP `
  -LocalPort 30301-30304 `
  -Profile Private `
  -RemoteAddress LocalSubnet
```

`LocalSubnet` 将访问范围限制在本地子网，避免不必要地向其他网络开放服务。

检查规则：

```powershell
Get-NetFirewallRule `
  -DisplayName "YIUI RouterManager TCP 30300","YIUI Router UDP 30301-30304" |
  Format-Table DisplayName,Enabled,Profile,Direction,Action
```

如果重复执行 `New-NetFirewallRule`，可能创建同名或重复规则。规则已经存在且启用时无需再次添加。

## 六、配置 RouterManager URLACL

RouterManager 使用 Windows `HttpListener` 监听：

```text
http://*:30300/
```

先检查是否已经注册：

```powershell
netsh http show urlacl url=http://*:30300/
```

如果能看到以下内容，则无需重复添加：

```text
Reserved URL : http://*:30300/
Listen       : Yes
```

只有在没有该记录，或者服务端明确报告 HTTP 监听权限错误时，才以管理员身份执行：

```powershell
netsh http add urlacl url=http://*:30300/ user=Everyone
```

URLACL 和防火墙不是一回事：URLACL 决定进程是否有权监听该 HTTP 地址；防火墙决定其他设备的数据能否进入电脑。两者都必须满足。

## 七、启动本地服务器

### 7.1 从 Unity 启动

停止 Unity Play，然后打开：

```text
ET → ServerTools
```

选择：

```text
StartConfig：Localhost
```

点击：

```text
Start Server(Single Process)
```

服务端控制台窗口必须保持打开。

### 7.2 从 PowerShell 启动

```powershell
Set-Location "E:\github\ET\YIUI\Bin"

dotnet .\App.dll `
  --Process=1 `
  --StartConfig=StartConfig/Localhost `
  --Console=1
```

也可以运行：

```powershell
Set-Location "E:\github\ET\YIUI\Bin"

.\App.exe `
  --Process=1 `
  --StartConfig=StartConfig/Localhost `
  --Console=1
```

必须以 `Bin` 作为工作目录。服务端通过相对路径读取 `../Config`，从其他目录启动可能找不到配置。

停止服务端时，在控制台按 `Ctrl+C`，或关闭服务端控制台窗口。

### 7.3 “起服模式”的说明

当前 `ServerTools` 界面包含“正式 / 开发 / 压测”选项，但现有启动代码没有把这个选项传递给服务端，所以三者目前没有实际差异。

真正决定加载哪套服务器配置的是 `StartConfig`：

- `Localhost`：本机开发和局域网真机测试。
- `Release`：正式部署配置。
- `Benchmark`：压力测试配置。
- `RouterTest`：Router 专项测试配置。

Android 真机连接本机服务端时使用 `Localhost`。

## 八、验证服务器监听状态

服务端启动后，另开一个 PowerShell 窗口。

检查 RouterManager TCP 30300：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 30300
```

检查 Router UDP 30301～30304：

```powershell
Get-NetUDPEndpoint |
  Where-Object { $_.LocalPort -ge 30301 -and $_.LocalPort -le 30304 } |
  Sort-Object LocalPort |
  Format-Table LocalAddress,LocalPort
```

如果查询不到端口，说明服务端没有成功启动、启动后退出，或者读取的不是预期配置。

## 九、分层验证连接

### 9.1 电脑本机验证

```powershell
Invoke-WebRequest "http://192.168.1.7:30300/get_router"
```

正常情况下会返回路由 JSON。`Routers` 应类似：

```text
192.168.1.7:30301
192.168.1.7:30302
192.168.1.7:30303
192.168.1.7:30304
```

如果返回的 Router 仍为 `127.0.0.1`，说明 `OuterIP` 没有正确修改、Luban 配置没有重新生成，或服务端没有重启。

### 9.2 手机浏览器验证

在手机浏览器中打开：

```text
http://192.168.1.7:30300/get_router
```

浏览器能够返回 JSON，说明手机到电脑的 TCP 30300、RouterManager 和基础局域网连通性正常。

### 9.3 APK 验证

手机浏览器成功后再启动 APK。如果浏览器成功但 APK 失败，重点检查：

- APK 中的 `RouterHttpHost` 是否仍为旧地址。
- 是否重新编译了热更新 DLL 和资源包。
- Android 是否允许明文 HTTP。
- Router JSON 返回的 30301～30304 地址是否为电脑局域网 IP。
- UDP 30301～30304 是否已放行。

## 十、常见问题定位

### 电脑和手机都无法打开 `/get_router`

优先检查：

- 服务端控制台是否仍在运行。
- TCP 30300 是否处于监听状态。
- 服务端是否报告配置、MongoDB、端口占用或 HTTP 权限错误。
- 是否从 `Bin` 工作目录启动。

### 电脑能打开，手机打不开

优先检查：

- Windows 防火墙规则是否启用且 Profile 与当前网络类型匹配。
- 手机和电脑是否处于同一子网。
- 路由器是否启用了 AP 隔离或访客网络。
- 手机是否开启了 VPN、代理，或实际在使用移动数据。

### 手机浏览器能打开，APK 仍然连不上

优先检查 APK/热更新资源是否包含最新地址，以及 Android 明文 HTTP 和 UDP Router 端口。

### APK 在联网前就报错

如果 Android 日志出现 `MissingMethodException` 等热更新错误，说明 APK、热更新 DLL 或 AOT 元数据可能不一致。应重新执行 HybridCLR 生成、复制 AOT DLL、构建 YooAsset 资源并重新出包。此类错误发生在联网逻辑之前，单纯修改服务器地址无法解决。

## 十一、推荐排查顺序

按以下顺序逐层验证，可以快速定位问题所在：

1. 确认电脑 WLAN IPv4。
2. 修改客户端 `RouterHttpHost`。
3. 修改服务端 `OuterIP` 并执行 `GenConfig.bat`。
4. 确认 Android 允许 HTTP。
5. 确认 URLACL 和 Windows 防火墙。
6. 使用 `Localhost` 配置启动 Single Process 服务端。
7. 检查 TCP 30300 和 UDP 30301～30304。
8. 电脑访问 `/get_router`。
9. 手机浏览器访问 `/get_router`。
10. 最后测试 APK，并根据 Android 日志继续定位。

## 十二、正式发布前的 HTTP 安全检查

本地测试使用的地址为：

```text
http://192.168.1.7:30300/get_router
```

这是未加密的明文 HTTP。它适合可信任局域网内的临时开发测试，但不应直接用于正式发布。明文通信可能被监听或篡改，客户端也无法确认返回路由列表的服务器身份。

正式发布前应完成以下调整：

1. 为 RouterManager 准备正式域名，例如 `router.example.com`。
2. 配置有效且受 Android 信任的 TLS 证书。
3. 通过 HTTPS 反向代理或服务端 HTTPS 监听暴露 `/get_router`。
4. 将客户端的 `RouterHttpHost` 改为正式域名，并让请求使用 `https://`。
5. 确认正式环境返回的 Realm、Router 地址均为客户端可访问的公网地址或域名，不能包含 `127.0.0.1` 或开发机局域网地址。
6. 在 Android 真机上验证 HTTPS 证书链、路由获取、登录和断线重连。
7. 验证完成后，将 Unity 的 `Allow downloads over HTTP` 从 `Always Allowed` 改为 `Not Allowed`，然后重新构建正式 APK/AAB。

Unity 设置路径：

```text
Edit
→ Project Settings
→ Player
→ Android
→ Other Settings
→ Configuration
→ Allow downloads over HTTP
→ Not Allowed
```

正式包中的项目设置应对应为：

```text
insecureHttpOption: 0
```

推荐将开发环境与正式环境的地址、HTTP 策略分开管理，避免把局域网 IP 或 `Always Allowed` 误带入正式包。发布前至少检查：

```text
[ ] RouterManager 使用 HTTPS
[ ] TLS 证书有效且证书链完整
[ ] 客户端不再请求任何 http:// 地址
[ ] Router/Realm 返回正式可访问地址
[ ] Allow downloads over HTTP = Not Allowed
[ ] 使用 Release APK/AAB 在真机完成登录测试
```
