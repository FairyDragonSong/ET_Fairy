# 020.20 Windows 生产目录 ACL 门禁

状态：真实 Windows ACL 规则与攻击场景通过；生产专用服务账号和目标目录 ACL 待部署。

## 目标

此前的签名和不可变槽位仍依赖操作系统权限边界。本项提供生产前只读检查：发布槽位只能由服务身份读取执行，运行/部署状态目录允许受控写入，Secret 和私钥只能读取不能修改，并拒绝宽泛主体和重解析点绕过。

## 实现

- `Test-ServerFilesystemAcl.ps1` 要求 ReleaseRoot、RuntimeRoot、DeploymentStateRoot、SecretRoot 和私钥全部位于仓库外，且可写目录/Secret 不得位于不可变 ReleaseRoot 下。
- 服务身份必须是可解析的专用非管理员 SID；拒绝 LocalSystem、Administrators、Everyone、Authenticated Users 或 Builtin Users 作为服务身份。
- ReleaseRoot：服务身份具备 ReadAndExecute，但不具备写入、删除、改 ACL 或取得所有权。
- RuntimeRoot 和 DeploymentStateRoot：服务身份具备 Modify；Everyone、Authenticated Users 和 Builtin Users 不得写入。
- SecretRoot 与列出的私钥：服务身份具备 Read，但不得写入；三个宽泛主体不得读取。
- 所有受保护根、Release/State/Secret 子树和私钥拒绝 ReparsePoint，避免目录联接或符号链接越界。
- 脚本只检查、不修改 ACL，生产权限应由管理员/IaC 显式设置并审计。

## 自动化验证

`Test-FilesystemAclGovernance.ps1` 在临时目录建立真实 Windows DACL，以 `LOCAL SERVICE` SID 模拟专用非管理员服务身份。安全权限通过；Everyone 写发布目录、Users 读 Secret、服务身份写 Secret、状态目录只有只读权限四种配置均被拒绝。GitHub Windows CI 已加入门禁。

## 当前本机边界

本机 `D:\Program Files\ET\_Env\server` 当前继承 `Authenticated Users: Modify`，它是工具安装目录，不是已建成的生产部署/Secret 目录，也不满足本门禁。当前会话不是管理员，未擅自改动该目录 ACL、创建系统服务或生产服务账号。

生产应创建独立低权限账号，并把发布安装身份、运行身份、安全/备份签名身份分离。该检查基于 DACL 中直接匹配的 SID；部署时仍需审计服务账号的组成员关系，确保它没有通过其他管理员或高权限组获得额外权限。

## 回滚

本项验证器不修改系统。调整生产 ACL 前应导出原 SDDL；配置错误时使用受控管理员身份恢复已审核的 SDDL，不应给 Everyone/Users 临时 FullControl。权限恢复后重新运行门禁和服务启动/回滚测试。
