# 018.8 登录与改密处理耗时分布

状态：2026-09-12 单测、真实链路样本数与 Prometheus 抓取验收通过；完整 018 仍实施中。

## 指标及范围

新增三个固定名称 Prometheus histogram：`et_realm_login_handler_seconds`、`et_gate_login_handler_seconds`、`et_password_change_handler_seconds`。每组包含累计 bucket、count 和 sum；桶边界为 1/5/10/25/50/100/250/500/1000/2500/5000 毫秒及 +Inf，导出单位统一为秒。

采用单调 Stopwatch 时间戳，从相应 Run 处理函数进入开始，到 finally 退出结束，包括函数中的认证、锁、数据库和内部 RPC 等待。成功、明确拒绝、限流和异常/提前返回均记录。采样不保存账号、IP、消息 ID 或异常文本；唯一标签为固定集合 le。

这些不是客户端端到端 RTT，不包含收到消息前的网络/排队、外层消息分发、回包序列化/传输，也不证明客户端收到了响应。Gate 耗时不包含随后的地图加载；改密幂等重试也会单独产生处理样本。进程强杀或永不返回的处理无法产生完成样本。

## 计数实现

计数和微秒整数总耗时在短锁内更新，导出每组 bucket/count/sum 时使用同一锁，避免跨字段并发读取造成直方图内部不一致。sum 以微秒截断存储并转换为秒，使用文化无关格式，避免中文/法文等区域设置破坏小数格式。

固定 3 组指标，不按请求或账号创建新序列。可以由采集平台计算近窗口分位数，但低样本量、bucket 分辨率和成功/拒绝混合都会影响解释；本项不提供生产延迟阈值或 SLO。
