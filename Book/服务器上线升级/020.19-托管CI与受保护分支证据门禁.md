# 020.19 托管 CI 与受保护分支证据门禁

状态：离线规则通过；远程分支未包含当前升级，GitHub 认证、真实 Actions 运行和分支保护待完成。

## 目标

本地测试通过不能证明代码经过托管流水线，也不能阻止管理员绕过审核直接推送。本项从 GitHub API 读取目标分支保护和精确 Commit SHA 的 Check Run，生成由独立观察身份签名、最长一小时有效的上线证据。

## 实现

- `Get-GitHubProductionGovernanceEvidence.ps1` 使用只读 Token 获取分支 HEAD、保护策略和目标提交的 Check Runs；Token 只从指定环境变量读取，不进入参数输出或证据。
- 目标 Commit 必须是当前分支 HEAD；必需 Check（默认 `server-baseline`）必须对同一 SHA 显示 `completed/success`。
- 分支保护必须开启严格状态检查、管理员同样受约束、至少 2 人批准、推送后旧批准失效、Code Owner 审核、最后推送由他人批准、会话全部解决，并禁止强推和删除分支。
- 证据只保存必要的保护策略摘要和 Check Run ID/链接，不保存 Token 或完整 API 响应；由与发布签名隔离的 RSA-3072 观察身份签名。
- `Test-GitHubProductionGovernanceEvidence.ps1` 重新验签、检查精确 SHA 和最长一小时有效期。该文件可作为 020.17 的 `ci-hosted-run` 证据。

## 自动化验证

`Test-GitHubGovernance.ps1` 离线验证安全基线，并确认测试证据冒充生产、审批少于 2 人、允许强推、CI 失败、分支 HEAD 不匹配以及证据篡改全部被拒绝。CI 工作流已加入此规则自测。

## 当前真实环境证据

- 远程：`https://github.com/FairyDragonSong/ET_Fairy.git`，公开仓库，默认分支 `main`。
- 本地工作分支：`tuanjie`；检查时远程 `refs/heads/tuanjie` 为 `d782bc56deb179676c1387f4d565a846895de027`，没有本轮 020 升级提交。
- 本机没有 GitHub CLI 登录；匿名读取分支保护 API 返回 401。因此尚未生成生产通过证据，也未声称 Actions 或保护策略已启用。
- 仓库当前没有 `.github/CODEOWNERS`。启用 Code Owner 强制审核前需由用户确认真实生产维护者/团队，不能猜测身份；个人仓库若无法提供两个独立批准人，不满足本门禁。

## 生产验收

推送候选分支后，由仓库管理员配置规则和真实 CODEOWNERS，并让不同人员完成审批。使用只读细粒度 Token 运行取证脚本，随后以验证器复验。任何提交变化都会改变 SHA，必须重新运行 Actions、重新审核并生成新证据。

## 回滚

本项不修改远程设置。证据失败时阻断发布，不降低审核人数或允许管理员/强推绕过。修复远程策略或重新运行 CI 后生成新的证据文件；旧证据按审计周期保留。
