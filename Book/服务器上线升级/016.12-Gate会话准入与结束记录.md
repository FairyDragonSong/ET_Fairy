# 016.12 Gate 会话准入与结束记录

状态：2026-09-12 本机准入/结束记录验收通过；不代表完整设备管理或生产审计系统完成。

## 实现与含义

.NET Gate 在一次性票据消费、账号状态与版本核对后，角色加载/会话绑定之前，以 majority 写入 `ET.Server.AccountSessionJournal`。每次准入使用独立随机 ID；数据库写入失败拒绝该次登录，不绑定新会话。写入等待上限 3 秒；已超时且提交结果不确定的记录可能仍存在，不能将记录存在解释为登录成功响应已送达。

准入成功的 Session 挂载记录组件。组件随连接销毁时，尝试将该条 `admitted` 记录更新为 `ended`，补充 UTC 时间和断线错误码；幂等条件避免重复覆盖结束时间。账号状态版本来自此次经过核对的 Gate Key。

记录仅包含随机记录 ID、内部账号 ID、凭据版本、进程号、Gate ID、分区、时间、状态及通用断线错误码。不收集密码、Token、Gate Key、账号名、原始 IP 或设备指纹。这里的账号 ID 仍是需要访问控制的用户关联数据，不是匿名数据。

`admitted` 只表示准入记录已写入，不是在线状态。角色加载失败、响应丢失、进程崩溃、停机销毁顺序或断线时数据库不可用，可能留下没有结束标记的记录。结束写入是有界尽力操作，不阻止角色下线保存；失败输出脱敏事件日志，尚无持久重试队列。

## 部署与数据

- Gate 启动时建立 `ix_session_account_opened`（AccountId 升序、OpenedAtUtc 降序），完成后再监听连接；失败不继续初始化网络。
- 新集合不修改旧账号、角色或协议编号。当前启动身份需可创建该索引；运行期需 insert/update。生产迁移身份与运行身份分离仍待交付工程完善。
- 暂不设置 TTL 或批量删除；数据保留期限需在 016 数据策略项确定后实施，不能把无限保留作为正式上线方案。
- 目前仅 .NET 宿主接入，Unity 服务端构建不引用这部分实现；Unity/微信客户端设备声明、登录来源摘要、设备列表和单设备撤销未完成。

## 验收与回滚

`Test-Gameplay.ps1 -SelfCredentials` 增加直接读取真实数据库的检查：两个准入记录分别关联改密前后版本；旧会话撤销后旧记录结束，正常客户端断开后新记录结束；未授权及旧票据被拒绝不产生准入记录；字段白名单和查询索引正确。

本轮结果：Release 编译 0 警告/0 错误，15 项回归、健康/指标/停机和生产配置门禁通过；`-SelfCredentials` 全部通过，新增 `session-journal-admission-version-revocation-disconnect-index-minimal-fields` PASS；`-Governance` 封禁、解封、版本撤销、事务竞争、恢复地图、主动撤销和软注销回归全部通过。两次游戏进程均正常停机。

证据位于本机 `_Env/mongo-local/evidence/gameplay-self-credentials.json`、`gameplay-governance.json` 及时间戳报告，包含父提交与工作区变更标记。

仍需专项覆盖会话集合写入权限拒绝、插入超时、断线写入失败补偿、强杀后对账、多机器关联及管理查询权限。不会用本机正常写入证明这些场景通过。

2026-09-12 新增真实压力证据：[014.5](014.5-3000人停机排空与有限并发保存.md) 中 3000 人集中断开/停机阶段出现 1387 条 account_session_journal_failed（stage=disconnect）。角色保存和进程正常退出已通过，但会话结束记录可靠写入与失败补偿仍未完成，需专项定位并复验，不能把本轮容量 PASS 当作审计完整性通过。

回滚本项代码可停止新增记录；保留集合和索引供取证，不自动删除历史记录。回滚后不再具备会话准入记录写入失败时的拒绝门禁。
