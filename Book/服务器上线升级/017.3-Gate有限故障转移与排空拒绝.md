# 017.3 Gate 有限故障转移与排空拒绝

状态：本机实现与回归通过；真实独立 Gate 进程强杀及跨主机切换待验收。

## 目标与取舍

原 Realm 按账号哈希固定选择一个 Gate。目标 Gate 不可达时，即使同区服还有健康 Gate，登录也会失败。另一方面，一次性 Gate Key 只有 20 秒有效期且不承载资产，把它放入共享数据库会增加写入、清理和密钥消费事务，却不能解决客户端已连接 Gate 的迁移。

本项保持 Key 由目标 Gate 本地签发和一次消费，增加有界候选转移：首选 Gate 失败时只尝试同区服尚未尝试过的 Gate，每个 Gate 最多一次。这样避免无限重试和重试风暴，也不声称连接可以无损迁移。

## 实现

- 候选顺序仍以账号哈希为起点，之后循环遍历同区服 Gate；同一账号和拓扑得到确定顺序。
- 仅对目标不存在、RPC 超时、基础设施异常，以及 Gate 正在排空返回的服务不可用错误尝试下一候选。
- 协议类型错误或其他远端业务错误不重试，防止掩盖版本不兼容和程序缺陷。
- Gate 收到全局停机请求后拒绝签发新 Key，Realm 可转向其他进程中的 Gate；单进程 Localhost 全局停机时所有 Gate 都会拒绝，这是预期行为。
- RPC 响应不确定时，旧 Gate 可能短暂保留一个客户端从未收到的 Key；它仍只存在于该 Gate、20 秒后删除且无法猜测，不执行跨 Gate 复制。

## 验证

- Release 构建 0 警告、0 错误。
- 单元测试验证三个 Gate 的候选不重不漏、顺序稳定、只对白名单故障重试且拒绝越界尝试。
- 完整第一阶段回归和真实登录链路继续通过；现有 Gate Key 重放测试继续证明同一 Key 只能消费一次。

本机 Localhost 把两个 Gate 放在同一进程，无法用“杀进程”只杀其中一个 Gate。因此本项没有伪报真实独立进程故障切换通过；该证据需要 Release 多进程环境或专用故障注入环境。

## 部署与回滚

无新增配置和数据库迁移。部署后 Realm 会在明确的可恢复故障上有限尝试其他 Gate。回滚恢复固定 Gate 行为，不影响已签发 Key；回滚会重新引入单个不可达 Gate 阻断其哈希账号登录的问题。

## 下一步

若首发仍使用单主机，可先用现有 Windows 服务监督器恢复故障进程。进入多主机部署前，再补充 Gate 实例健康状态的短期熔断、独立进程强杀和连接排空实测；不在没有真实多进程环境时宣称完成高可用。
