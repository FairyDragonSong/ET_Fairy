# 018.17 有界日志轮转与磁盘预算检查

状态：2026-09-12 本机实现与验证；完整生产日志治理仍未完成。

## 现状与启用

原配置按 logger/小时分文件，不设大小/归档数限制；Debug 目标重复收录 Trace 至 Error。本轮首次盘点历史日志约 7.68GiB，保留原文件和失败证据，不自动迁移或删除。

新增 `Config/NLog/NLog.Bounded.config`。在 .NET 进程启动前设置 `ET_LOG_PROFILE=bounded`；未设置或 legacy 保持旧配置。未知值在 App 启动入口退出 3。本机玩法工具可用 `-BoundedLogs` 显式选择，并在报告中记录 LogProfile 与 OS 进程 ID。

目录为 `Logs/bounded/<OS进程ID>`，每个进程固定 info/warn/error 三类文件，logger 身份写入日志行，不按 Fiber 创建文件。Info、Warn 分流；Error 目标包含 Fatal；Trace/Debug 不写入。此格式是分隔文本，不冒充已实现统一 JSON 日志或消息脱敏。

## 大小与保留策略

每类文件达到约 64MiB 后轮转，Rolling 归档最多 4 个，最旧归档由 NLog 淘汰。测试中只淘汰本次新建临时目录的测试归档；未删除历史 Logs 文件。

三类各 1 活动文件 + 4 归档，规划量级约 960MiB/进程目录，**不是硬磁盘上限**：单条消息和批次可能超出轮转阈值；不同 PID 目录累计增长；PID 复用时可能继续使用同名目录。没有跨进程总量淘汰或按天过期。

每类异步队列最多 4096 条，满时 Block，不默认丢弃；限制的是条数，不是字节，单条日志大小仍未限制。阻塞会影响 Fiber 延迟，需要压测和告警，不能据队列有限认定性能无影响。正常主流程在 World 清理后调用 NLog Shutdown，刷新关闭日志；强杀、磁盘失败或异常退出不保证最后日志保存。

## 只读预算工具与测试保护

`Tools/ServerOps/Measure-LogBudget.ps1` 默认检查整个 Logs，预算 10GiB、所在磁盘可用空间下限 5GiB；参数可调整。JSON 报告包含文件数、总字节、预算与低空间标志；超预算或低空间退出 1，正常退出 0。拒绝直接以盘符根目录为目标，不读取日志正文，不删除文件。

这只是可执行检查，不是定时监控、磁盘配额或生产自动清理。旧日志也计入总量。多文件读盘是非原子快照，不保证并发写入时精确瞬时总量；目录权限不足会报错，不按零处理。

CapacityProfile 的已有资源保护增加工作区磁盘至少 5GiB 可用的检查，触发时本轮测试失败并清理自身 ET 进程。检查依赖收到进度输出且间隔至少 5 秒，不能作为实时硬限额；不停止 MongoDB 或其他应用，也不扩大生产服务器行为。
