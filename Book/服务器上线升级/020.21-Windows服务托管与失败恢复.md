# 020.21 Windows 服务托管与失败恢复

状态：签名配置、组件清单、服务策略和本机工具校验通过；管理员注册及真实重启/关机演练待执行。

## 目标

把 020.13 的 A/B 监督器交给 Windows SCM 托管，避免交互终端退出后服务消失，并限制崩溃重启风暴。服务启动参数不能携带 Secret，也不能通过测试开关绕过发布、状态和紧急停服门禁。

## 实现

- `New-ServerSupervisorConfiguration.ps1` 将监督器全部生产参数标准化为仓库外 JSON，并由 RSA-3072 配置身份签名；缺少必需参数或出现 `AllowTestPlan`、`AllowDirtyTestArtifact`、故障注入/测试退出开关时拒绝。
- `Start-ServerSupervisorFromConfiguration.ps1` 启动前重新验签、核对 KeyId/公钥指纹和参数白名单，再调用现有监督器；WinSW XML 只包含配置路径，不包含数据库密码、Token 或其他 Secret 值。
- `New-WindowsServiceHostManifest.ps1` 生成 WinSW XML，并把 WinSW、PowerShell、启动器、签名监督配置及 XML 的 SHA-256 固化到独立签名清单。服务托管、监督配置和发布制品三个签名身份必须分离。
- 服务账号固定为 `NT SERVICE\<ServiceId>` 虚拟账号；自动延迟启动，停止等待 60 秒，系统预关机等待 3 分钟。
- 异常退出只在 10 秒、30 秒后重启两次，第三次停止并等待人工处置；稳定运行一小时后重置失败计数，避免无限快速重启掩盖签名/配置故障。
- `Test-WindowsServiceHostManifest.ps1` 每次注册前复验签名、全部组件哈希和 XML 策略。测试清单默认不能用于生产。

## 本机工具安装

- 已从 WinSW 官方 GitHub Release 安装稳定版 2.12.0 x64 到 `D:\Program Files\ET\_Env\tools\winsw-2.12.0\WinSW-x64.exe`。
- 文件大小 18,243,033 字节，版本资源为 `2.12.0.0`，固定 SHA-256：`05b82d46ad331cc16bdc00de5c6332c1ef818df8ceefcd49c726553209b3a0da`。
- 外部 `packages.json` 已记录来源和摘要。上游资产没有 Authenticode 签名且 Release API 未提供摘要；生产应由内部制品库复核、签名并保留来源证明。本次固定摘要防止后续静默替换，但不能反向证明首次发布资产供应链未受攻击。

## 自动化验证

`Test-WindowsServiceHosting.ps1` 使用三把临时 RSA-3072 密钥验证签名监督配置、组件清单、自动延迟启动、有限失败恢复和优雅停止。测试清单冒充生产、启动器被改、重新签署但放宽重启策略、复用配置签名密钥作为托管身份均被拒绝。Windows CI 已加入该门禁。

当前会话不是管理员，因此未注册服务。没有生产发布槽位、真实签名监督配置和专用服务 SID ACL 时，注册一个空壳服务不会构成有效验收。正式主机需按 020.20 配置 ACL 后，用管理员身份安装服务，验证开机启动、进程崩溃两次恢复/第三次停止、SCM Stop 优雅排空、系统关机以及紧急停服不被 SCM 反复拉起。

## 回滚

停止并卸载 WinSW 服务前先保留服务配置、签名清单、SCM 事件和运行日志。卸载服务不删除发布槽位、状态链、Secret 或备份。恢复旧托管方式必须仍调用签名监督配置入口，禁止直接执行 `App.exe` 绕过门禁。
