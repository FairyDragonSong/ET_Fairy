# 016.11 自助改密审计权限拒绝验收

状态：2026-09-12 本机真实数据库权限拒绝验收通过；完整 016 仍在实施中。

## 目的与实现

016.10 通过代码异常注入验证回滚，本项进一步验证 MongoDB 真正拒绝审计写入时不会留下密码变更。

`Test-Gameplay.ps1 -SelfCredentials` 在本机 `et-local-rs` 的 `ET_LOCAL_GAMEPLAY` 数据库创建随机临时角色和账号：账号集合仅 find/update，账号状态审计集合仅 find，不授予 insert。随机凭据通过测试子进程环境传递，不写入仓库、报告或命令行参数。

实际调用同一个 `UserPasswordStore.Change`，使用独立数据库连接及事务。只在账号更新已经返回成功后设置观察标记，不主动抛异常；审计 InsertOne 由 MongoDB 权限检查拒绝。测试要求观察标记成立、异常码严格为 13，然后用原测试连接复查账号密码哈希、盐、StateVersion 均保持不变，操作审计数量为 0。

临时角色/账号名称严格匹配 `et_self_test_` 加 32 位十六进制；脚本只接受指定本机测试数据库和副本集。finally 删除精确的临时用户/角色，检查不存在；业务测试账号和审计证据保留。服务器尚未启动时的失败路径使用明确的启动标记，保证不会因为读取未启动 Process 的属性而跳过清理。

## 结果

- `Test-Phase1.ps1`：Release 编译 0 警告/0 错误、15 项回归、健康/指标/优雅停机、生产不安全配置拦截通过。
- `Test-Gameplay.ps1 -SelfCredentials`：新增 `self-password-real-audit-permission-denied-code13-rollback` PASS；原事务竞争、异常回滚、真实网络改密、限流、旧凭据撤销均 PASS，正常停机退出码 0。
- 临时测试用户/角色清理成功；不删除测试账号或审计。
- 本机证据：`_Env/mongo-local/evidence/gameplay-self-credentials.json` 与时间戳报告，含父提交及工作区变更标记。报告中的 Passed 表示游戏验收和停机结果，清理失败会另使脚本退出失败。

## 边界与回滚

这是单机 TLS 副本集上的真实权限拒绝，不证明跨机器网络分区、提交响应丢失、生产写关注超时或生产最小权限配置已经验收。生产密码登录门禁保持不变；不新增产品端点或业务权限。

回滚本项测试代码即可，无业务数据库迁移。意外中断如来不及 finally，需依据本轮精确临时账号名核查清理，不可批量删除其他数据库用户。
