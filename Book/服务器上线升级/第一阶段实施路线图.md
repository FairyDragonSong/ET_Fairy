# 第一阶段实施路线图

## 目标

第一阶段把当前 ET 示例服务器升级为具备基础安全、真实认证、持久化闭环、可运维性和自动化回归能力的试用服务器。当前首先支持账号密码，后续微信小游戏登录通过认证提供方扩展接入。

## 固定实施顺序

| 顺序 | 阶段 | 主要内容 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 登录安全 | 删除密码日志、一次性 Gate Key、防重放 | 日志不含密码；登录 Key 只能消费一次；重复请求被拒绝 |
| 2 | 账号认证 | 账号模型、密码哈希或平台 Token 验证、登录限流 | Realm 在签发 Gate Key 前完成认证；密码不明文落库；失败请求受限流保护 |
| 3 | 持久化闭环 | 账号/角色加载、保存、下线落库、MongoDB 索引 | 关键数据生命周期闭环；唯一约束明确；可执行备份恢复 |
| 4 | 运维基础 | 健康检查、结构化指标、优雅停机 | 部署平台能判断存活/就绪；核心指标可观测；停机前停止接入并保存 |
| 5 | 自动化验证 | 登录、重连、重复登录、攻击场景和数据恢复测试 | 核心场景可重复执行，并形成上线前自动化验证结果 |

## 维护方式

1. 按顺序实施；安全依赖允许拆成多个可独立验证的升级项。
2. 每项开始时创建编号文档，并在总索引标记“实施中”。
3. 代码、配置、部署和数据变化必须同步更新该项文档。
4. 构建或测试失败时不得标记完成；未覆盖的运行时验证必须如实记录。
5. 每项完成后创建一个独立 Git 提交；提交信息包含升级编号，提交哈希以 Git 历史为准。
6. 下一项开始前确认工作区没有混入无关变更。
