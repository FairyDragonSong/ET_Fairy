# 018.16 Map 积压告警与恢复通知闭环

状态：2026-09-12 实现，本机验收结果见下；完整商业上线仍未完成。

## 流程

运行 `Tools/ServerOps/Test-GameplayMetrics.ps1 -Notifications`。不带开关仍保留 018.15 的纯采集/规则状态模式。

带开关时复用本机固定版本 Alertmanager 0.34.0，监听 127.0.0.1:30910，关闭集群监听；测试 webhook 监听 127.0.0.1:30911。Prometheus 将 ETLocalMapMailboxBacklog 交给 Alertmanager，再通过独立 Bearer 凭据发送到测试接收端。

20 客户端玩法负载后制造真实邮箱锁等待；采到 firing 且接收端已记录 firing 通知，才释放锁。确认采集恢复和规则清除后，还必须收到同一 fingerprint 的 resolved 通知，且时间不早于 firing，再允许测试结束。缺失、错配或子进程退出都不判通过。

接收端只允许已知两组测试：metrics-test GUID 目录对应 ETLocalTargetDown / et-primary、et-peer；gameplay-metrics GUID 目录对应 ETLocalMapMailboxBacklog / et-gameplay。不允许任意告警名或转发目的地。沿用只写状态、job、告警名、fingerprint、接收时间的最小日志，不保存原始 payload 或凭据。

## 边界

这是本机测试 webhook 的真实送达，不是微信、邮件、短信或值班人员确认。报告 LocalNotificationVerified 仅表示本轮 firing/resolved 验收，ExternalNotificationVerified 保持 false。

路由 group_wait=1s、group_interval=1s、repeat_interval=1m，启用 send_resolved；沿用 inflight>0 持续 3 秒的测试阈值，不能直接部署为生产 SLO。未验证本条规则的通知重试、长时接收端离线、重复通知处理、Alertmanager 强杀恢复或集群 HA。
