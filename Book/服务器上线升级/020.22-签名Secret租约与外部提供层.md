# 020.22 签名 Secret 租约与外部提供层

状态：运行时、监督器、签名工具和攻击场景通过；生产 Secret Manager/Agent 待接入。

## 目标

受限文件权限只能说明“谁能读写”，不能证明 Secret 来自受信提供方、属于当前部署、仍在有效期内或签署后没有被替换。本项在云厂商无关的文件挂载方式上增加最长 24 小时的 RSA-PSS 签名租约，使 ET 对 Mongo URI、密码密钥环、指标 Token、管理 URI/信任表等受管文件执行来源与内容验证。

## 实现

- `New-SecretLease.ps1` 由外部 Secret Agent/KMS 身份生成租约，绑定 LeaseId、DeploymentId、Provider、递增 Generation、有效期以及每个 Secret 的相对路径、大小和 SHA-256。
- 租约签名身份使用 RSA-3072+，并按公钥指纹强制与发布制品签名身份分离。租约、签名和信任公钥位于仓库外 SecretRoot；私钥不交给游戏进程。
- `SecretLeasePolicy` 验证 RSA-PSS/SHA-256、签名公钥指纹、DeploymentId、KeyId、最长 24 小时有效期、1–64 个唯一文件、路径边界、重解析点、单文件 1 MiB 上限、大小和固定时间哈希比较。
- `ProductionSecretPolicy.ReadManagedFile` 在配置租约后，每次读取受管 Secret 都重新验证租约和完整库存，并拒绝未列入租约的文件。动态指标 Token 轮换因此同样受保护。
- `Invoke-ServerSlotSupervisor.ps1` 的非测试生产路径强制提供完整租约，在启动槽位前先由 `Test-SecretLease.ps1` 验证，并向子进程注入 `ET_SECRET_LEASE_REQUIRED=1` 及租约元数据。
- 签名监督配置同时强制包含租约、签名、信任、KeyId 和绑定的发布公钥，测试开关不能绕过。

## 自动化验证

- .NET 回归新增“签名 Secret 租约与文件完整性”，覆盖合法读取、未列入文件、内容替换、过期、超过 24 小时、跨部署重放和部分配置。
- `Test-SecretLeaseGovernance.ps1` 验证两份 Secret 的签名租约，并拒绝内容篡改、跨 DeploymentId、超大 Secret 和复用发布签名密钥。
- `Test-WindowsServiceHosting.ps1` 已迁移为强制包含 Secret 租约参数；020.13 测试计划仍可使用明确的测试路径，不影响真实发布门禁。
- GitHub Windows CI 已加入 Secret 租约治理测试。第一阶段自动化总数由 25 增至 26。

## 信任与生产边界

租约不加密 Secret，也不替代 020.20 的 ACL；它提供来源、部署绑定、有效期和篡改检测。生产 Secret Manager/Agent 必须原子写入新版本文件和租约，确认所有实例接受新 Generation 后再撤销旧凭据。签名私钥应位于 KMS/HSM 或隔离 Agent，服务账号只能读取信任公钥、租约和业务 Secret。

当前没有选定云厂商或生产 Secret Agent，因此没有伪造接入成功证据。正式上线需要用真实 Agent 完成续租中断、租约过期失败关闭、旧新凭据重叠、提供方不可用和多实例一致性演练。

## 回滚

新租约失败时保留当前仍有效租约和 Secret，不覆盖旧文件；修复提供方后创建更高 Generation 的新 LeaseId。不得延长或重签已经泄漏的凭据。若回滚到 020.22 之前的二进制会失去租约强制验证，因此商业服务禁止此类安全降级。
