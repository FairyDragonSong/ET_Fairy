# 018.19 Gate 登录可用性 SLI 结果分类

状态：代码与本机自动化验证通过；生产聚合、SLO 和端到端进入地图指标待完成。

## 目标

018.18 只能说明 Realm 完成账号认证并取得 Gate Key。客户端随后仍可能在 Gate Key 消费、账号版本复核、会话审计、角色加载或重复登录状态恢复阶段失败。本项为 Gate 登录处理器增加互斥结果分类，避免 Realm 成功率掩盖后半段故障。

## 实现

- `et_gate_login_attempts_total`：Gate 登录处理器收到的全部请求。
- `et_gate_login_successes_total`：账号、会话记录、角色状态与 Session 绑定全部完成，并已设置返回 PlayerId。
- `et_gate_login_rejections_total`：无效、过期或重放 Gate Key，以及账号状态/凭据版本已失效。
- `et_gate_login_service_errors_total`：账号数据库不可用、会话记录失败、角色加载/保存状态未恢复、内部玩家状态冲突、房间恢复异常和其他未处理异常。
- `et_gate_login_failures_total` 由同一快照中的拒绝与服务故障相加，保持总数与分类一致。

所有指标均为无动态标签的 Prometheus counter。处理器通过 `outcomeRecorded` 保证每个已完成请求只进入一个终态；未到达终态就抛出的异常按服务故障记录后继续抛出，不吞掉原异常。

Gate 可用性 SLI 可按窗口计算 `success / (success + service_error)`，拒绝数不进入服务可用性分母。请求处理中间态会使 attempts 暂时大于终态总和，不能将其直接当成永久数据丢失；应结合处理耗时直方图和合理窗口判断。

## 验证

- Release 编译和 26 项第一阶段回归验证五个 Gate 计数、各 1000 次并发写入、总数一致、类型元数据、非法分类拒绝及调用点架构约束。
- `Test-Gameplay.ps1` 的真实网络链路验证首次 Gate 登录计为成功，同一 Gate Key 重放只计为拒绝且不增加服务故障；后续继续覆盖重复登录、地图重连、Key 过期和限流。
- 首轮完整链路在新增检查之后暴露 Router 客户端仍附加 `?v=`、而 020.8 服务端已拒绝全部查询串的不一致。客户端现改用精确 `/get_router`；服务端 `no-store` 响应不需要该缓存破坏参数，源码回归禁止重新引入。
- 健康检查、指标导出、优雅停机和生产配置失败关闭必须继续通过。

## 边界

Gate 成功表示已绑定玩家 Session，不表示客户端已经成功进入 Map，也不覆盖客户端到入口之间的 DNS、TLS、代理或公网丢包。生产 SLO 仍需多进程集中采集、进程重启处理、最小样本量、维护窗口和 2000 在线长稳基线后再确定，不能把本地测试阈值直接作为商业承诺。

## 回滚

回滚 Gate 调用点和五个计数即可，不涉及协议或数据库迁移。依赖这些指标的查询和告警应先停用；否则缺失序列可能被错误解释为无故障。
