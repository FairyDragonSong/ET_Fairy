# 020.9 签名灰度计划与回滚决策门禁

状态：兼容契约、双人签名计划和健康决策在本机通过；生产流量编排、自动执行回滚与托管 CI 待目标平台验收，不可据此批准正式上线。

## 目标与边界

把 020.3–020.5 的“可信发布包”推进为可回答以下问题的发布门禁：候选版本能否与当前版本同时运行、候选迁移后旧版本能否读库回滚、谁请求并批准本次变更、观察证据是否可信，以及本轮应晋级、等待还是回滚。

本项不假设当前单机 ET 已有负载均衡器或服务编排平台。代码输出经过验签的机器决策，但不会自行修改 Windows 服务、DNS、防火墙或负载均衡权重。生产自动执行必须在实际部署平台接入并完成故障演练；仅生成 `ROLLBACK` 结果不等于流量和进程已经回滚。

## 已签名兼容契约

新发布 manifest 升级为 SchemaVersion 2，在原文件清单中增加：

- `DatabaseMinimumReadable`、`DatabaseMaximumReadable`、`DatabaseTarget`：分别表示服务器最低/最高可读数据库版本和启动迁移目标。
- `ProtocolSha256`：按稳定相对路径和原始内容汇总全部 Proto 源码，任何协议文件变化都会改变摘要。
- `RollingMode`：默认 `protocol-identical-only`；只有经过独立兼容评审并提供受限格式 Review ID，才能声明 `reviewed-backward-compatible`。

这些字段位于 ZIP 内逐文件 manifest，manifest 哈希又被外部 RSA-PSS attestation 绑定，不能在签名后修改。旧 SchemaVersion 1 包仍可执行单包完整性检查，但没有兼容契约，不能进入新旧版本灰度比较。

`DatabaseMigration` 不再用一个 CurrentVersion 混淆“可读范围”和“迁移目标”。启动时数据库版本必须在可读范围内，迁移完成后必须精确达到 Target。未来升级数据库结构时必须采用扩展/收缩顺序：先发布扩大 MaximumReadable、但不提高 Target 的兼容版本；全量稳定后再提高 Target；确认回滚窗口结束后才能收缩旧字段。不能把不可逆删除和应用发布放在同一轮灰度中。

## 候选版本门禁

`Test-ServerReleaseCompatibility.ps1` 会重新验签并逐文件验证当前包和候选包，然后要求：

- 候选 SemVer 严格高于当前版本，平台相同，二者都有 SchemaVersion 2 兼容契约。
- 当前版本的可读范围包含候选数据库 Target，保证回滚后仍可读。
- 候选版本的可读范围包含当前数据库 Target，保证灰度节点可先启动。
- 两版协议摘要相同；若不同，候选包必须携带 `reviewed-backward-compatible` 和 Review ID。

协议兼容声明是评审结论的签名绑定，不是自动证明。涉及消息字段语义、错误码、跨进程 RPC 状态机或客户端资源兼容时，仍需混合版本集成测试。

## 双人签名灰度计划

`New-ServerRolloutPlan.ps1` 只在兼容门禁通过后生成计划。调用者必须精确确认候选版本，并提供不同的 RequestedBy/ApprovedBy、不同 Key ID 和两把仓库外 RSA-3072 以上私钥。脚本比较公钥指纹，拒绝复制同一密钥冒充双人，也拒绝把发布制品签名密钥复用为发布审批密钥。

计划绑定当前/候选版本、提交和归档 SHA-256，以及唯一获准签发观察报告的监控 Key ID 和公钥指纹；监控密钥与发布、请求、审批密钥任一相同都会被拒绝。计划默认 5%→25%→50%→100% 波次、每波观察时间、错误率、就绪率和 P95 阈值，以及固定的崩溃、会话结束记录失败、角色保存失败回滚条件。计划有最长 24 小时有效期，三个文件均不可覆盖：JSON、Requester RSA-PSS 签名、Approver RSA-PSS 签名。

`Test-ServerRolloutPlan.ps1` 会重新验证两套发布包、兼容详情、两人签名、密钥职责分离、有效期、波次、阈值和回滚版本。RequestedBy/ApprovedBy 文本本身不是身份认证；生产公钥必须由组织 IAM/证书体系分发和吊销。

## 签名观察与决策

监控采集器应输出候选版本、包哈希、Change ID、波次、时间范围、样本/请求/错误数、就绪样本、P95、崩溃数、会话记录失败数和保存失败数，并用独立监控 RSA-3072 密钥签名。`Get-ServerRolloutDecision.ps1` 先重新验计划和两套发布包，再验监控签名及数据边界：

| 结果 | 退出码 | 含义 |
| --- | ---: | --- |
| `PROMOTE` | 0 | 观察时长和样本充分，所有阈值通过，可进入计划下一波。 |
| `HOLD` | 2 | 没有失败，但观察时间或样本不足；保持当前权重。 |
| `ROLLBACK` | 3 | 任一安全/健康阈值失败；平台控制器必须切回计划绑定的当前版本。 |

无效签名、字段缺失、错误版本/波次、时间超出计划窗口或非法数值按执行错误退出 1，不能当作健康通过。生产观察结束时间只容忍 30 秒时钟偏差；仅显式测试计划允许构造最多未来 5 分钟的短时样本，以免自动化自检等待五分钟。监控私钥必须与审批和发布签名密钥分离；采集器还需保护原始指标、时钟同步和计数增量正确性。

## 使用与回滚原则

正式计划不得使用 `-AllowDirtyTestArtifacts` 或 `-TestOnlyPlan`；测试计划的 `ProductionApproved=false`，生产验证默认拒绝。发布包、审批公钥、监控公钥和计划应进入不可变制品/审计存储，私钥不得写入命令行、仓库或计划。

回滚只允许使用计划中已重新验签的 Current 版本和 SHA-256，不能临时选择未知 ZIP，也不能拼接新旧 DLL。自动回滚应用版本不自动回滚数据库；本项通过“旧版可读候选 Target”避免必须反向迁移。若该条件不成立，兼容门禁直接阻断灰度，而不是寄希望于现场恢复备份。
