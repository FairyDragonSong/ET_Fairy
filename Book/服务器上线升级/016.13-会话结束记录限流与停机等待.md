# 016.13 会话结束记录限流与停机等待

状态：2026-09-12 实施集中结束写入限流、停机等待及专项验收；3000 真实在线原场景复验、失败补偿与强杀后对账仍待完成。

## 问题与证据边界

014.5 的 3000 人集中断线/停机出现 1387 条结束记录写入失败。旧实现从 Session Destroy 直接启动数据库更新，没有并发边界，也未加入 Gate 停机等待；每次更新有 3 秒超时。旧日志未记录异常类别，不能断言全部失败均由连接池等待超时引起。

## 本项实现

- 每个 Gate 独立记录待处理结束任务，最多 16 个数据库更新并发、4096 个待处理任务（包含在途）。数据库 3 秒超时从取得并发槽位后开始。
- 超出队列容量时拒绝该项、计失败并输出固定 reason=queue_full，不无限保留内存，也不伪报完成。该情况仍需要后续对账恢复，不是无损队列。
- NetComponent 移除触发 Session 清理后，Gate 参与者等待已跟踪任务结束；本 Gate 生命周期内发生过结束写入失败或溢出，则参与者报告失败。没有清空失败计数来绕过停机门禁。
- 保留总体 20 秒排空期限；到期仍未完成则由已有协调器判定失败。没有无限延长进程停机时间。
- 数据库异常仅记录 timeout/command/write/other 固定分类，不输出异常正文、账号、记录 ID、凭据或连接串。
- 已销毁会话的准入插入完成后，其结束清理也使用跟踪入口。仍需专项覆盖准入写入尚未完成时与整个 Gate 排空的竞争；本项不是全部登录任务排空。
- 不修改客户端协议、数据库字段或索引；新增 .NET Model 组件，需完整构建 Model/Hotfix 并重启，不作为热更无缝切换方案。

## 遗留与回滚

- 数据库故障后重试/可靠补偿、强杀后对账、进程启动实例标识、保留策略仍未完成；历史失败记录没有自动修补。
- 当前条件更新对已 ended 的重复调用无修改；尚未区分目标缺失与已经结束，后续补偿核验不能只依赖更新命令成功。
- 并发与队列上限按 Gate 独立，多 Gate 总量可能更大；不是全局数据库预算。
- 回滚本项会恢复不受控并发及未等待结束写入的停机行为；保留原记录和索引，不执行数据删除。
