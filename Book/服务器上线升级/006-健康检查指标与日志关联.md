## 运维接口

| 路径 | 用途 | 成功状态 |
| --- | --- | --- |
| `/health/live` | RouterManager 进程存活检查 | 200 |
| `/health/ready` | 核心 Realm/Router 配置已加载 | 200；未就绪为 503 |
| `/metrics` | Prometheus 文本指标 | 200 |

每个 HTTP 响应包含 `X-Request-Id`，未知路径返回 404，处理异常返回 500。接口复用 RouterManager 现有 HTTP 端口，部署时应通过防火墙或反向代理限制 `/health/*` 和 `/metrics` 只对内网监控系统开放；`/get_router` 仍按客户端接入需求配置。

## 指标与日志

指标包含进程启动时间、运行时长、工作集、托管堆、HTTP 请求/错误、登录尝试/成功/失败和角色保存成功/失败总数。登录关键日志使用稳定的 `event`、`trace_id`、`reason`、`error` 键值，不输出账号密码、Gate Key 或密码哈希。

当前指标是 RouterManager 进程内存指标；分进程部署时，登录和 Map 业务计数分别存在对应业务进程，后续应由独立监控端口或集中指标通道汇总。第一阶段先建立命名和采集格式，不将单个 RouterManager 的业务计数误表述为全服总数。

## 回滚

删除三个 Handler、指标类以及 HTTP 分发埋点即可回滚，不影响协议或数据库。回滚后监控系统必须同步移除对应探针，避免持续误报。
