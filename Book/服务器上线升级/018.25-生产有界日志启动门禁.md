# 018.25 生产有界日志启动门禁

状态：代码门禁和回归测试通过；生产服务账号、真实目录 ACL 与长稳磁盘水位待部署验收。

## 目标

018.17 已提供有界日志，但过去仅靠部署脚本主动设置；绕过监督器直接启动生产进程时仍可能选择 legacy 无界日志。本项只增加必要的生产失败关闭条件，不新增日志框架或配置层。

## 行为

当 `Develop=0` 时，`ProductionSecretPolicy.Validate` 现在同时要求：

- `ET_LOG_PROFILE` 必须精确为 `bounded`；缺失、legacy 或其他值均拒绝启动；
- `ET_LOG_ROOT` 必须是已经存在的绝对目录；
- 日志根不能是卷根、重解析点或应用目录内部，避免污染不可变发布槽位或经目录跳转写到非预期位置。

开发模式保持兼容，仍可显式使用 legacy。已有单机监督器已经设置 bounded，并把日志根指向发布槽位之外的 `RuntimeRoot/logs/<DeploymentId>`，因此正常受控部署无需新增参数。

## 验证

2026-09-13 本机验证：

- 合法的生产 bounded profile 与外部临时日志根通过；
- production + legacy、缺失/相对/不存在/卷根/应用目录日志根均被单元测试拒绝；
- Release 构建 0 警告、0 错误，26/26 回归通过；
- 没有执行多人在线或长稳测试，本项不改变业务协议、数据库结构或日志内容。

本轮编译包含工作区中另行存在的登录代码修改，但本项提交不包含那些文件；生产结论仍以提交后的干净基线复验为准。

## 生产边界与回滚

本项只保证生产进程不会在不安全日志配置下继续服务，不证明目录 ACL、磁盘配额、Collector 或异机后端已经部署。正式上线仍需用 020.20 验证服务身份只能写 Runtime 日志目录，并结合 018.23/018.24 验证磁盘告警和集中采集。

配置错误时应修复监督器签名配置、创建正确的外部 RuntimeRoot 并重新启动；不应回滚为 legacy 来恢复服务。若必须回退代码版本，仍应保留 `ET_LOG_PROFILE=bounded` 与外部 `ET_LOG_ROOT`，否则重新引入无界增长和发布槽位污染风险。
