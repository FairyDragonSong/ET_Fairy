# 016.25 账号导出保留与到期清理门禁

状态：2026-09-13 本机安全规则与删除夹具通过；生产任务调度、目录 ACL 和最终保留期限待验收。

## 目标与边界

016.24 生成的账号数据导出包含个人数据，不能无限期留存在服务器。本项增加明确的保留期启动门禁与安全清理工具，但不替业务方决定法定期限，也不清理数据库账号、角色、会话或不可变审计。

## 实现

- 当生产操作员信任表授予 `export` 时，启动配置必须同时提供 `ET_ACCOUNT_EXPORT_RETENTION_DAYS`，范围为 1–365 天；缺失或越界时失败关闭。
- `Remove-ExpiredAccountDataExports.ps1` 默认只审计；必须显式传入 `-Apply` 才执行删除。
- 操作员必须用 `ConfirmExportRoot` 再次提交完全相同的绝对目录。拒绝磁盘根目录、缺失目录和重解析点。
- 仅考察根目录直属、名称严格为 32 位小写 GUID 加 `.json` 的文件，不递归、不使用通配符删除、不处理其他文件。
- 删除前先验证所有过期候选：文件不是重解析点、大小为 1 字节至 16 MiB、JSON 可解析、SchemaVersion 为 1、文件名与 OperationId 一致且 AccountId/GeneratedAtUtc 有效。任一候选异常时整批失败，不删除已经验证的其他文件。
- 单次最多检查 10000 个文件。应用模式使用已核对的绝对文件路径逐个删除并验证文件消失，输出模式、截止时间、候选名和删除数量的结构化摘要。

到期清理是有意的永久删除，因为继续保留过期个人数据本身是风险。脚本不自动运行，生产调度前必须确认保留政策、备份继承规则和目录 ACL。

## 验证

- `Tools/ServerOps/Test-AccountDataExportRetention.ps1` 在唯一临时目录验证：错误根目录确认被拒绝；伪造 SchemaVersion 使整批失败且旧文件仍在；审计模式只选择过期文件且不删除；应用模式只删除过期合法导出，保留未到期文件。
- 测试只删除自身创建的临时夹具目录，完成后精确清理；没有触碰 016.24 的本机导出证据或用户文件。
- `dotnet build DotNet/DotNet.sln -c Release --nologo`：0 警告、0 错误。
- 离线保留测试已加入 `server-baseline.yml`，不依赖 MongoDB 或生产环境。

## 生产待办与回滚

上线前由业务、法务和安全共同确定真实保留期限、导出交付后的副本责任、备份中的过期方式和事故保全例外；由生产服务身份配置任务计划并验证 ACL 越权拒绝及删除审计送达。

回滚会移除启动保留期门禁和清理工具，但不会恢复已经按 `-Apply` 删除的过期导出，也不会自动删除任何剩余文件。
