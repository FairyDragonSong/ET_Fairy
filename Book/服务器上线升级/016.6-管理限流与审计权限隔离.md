# 016.6 管理限流与审计权限隔离

状态：本机管理入口范围已验收，生产部署与完整 016 仍未完成。

管理入口必须使用独立 `ET_ACCOUNT_ADMIN_MONGO_URI`、`ET_ACCOUNT_ADMIN_DATABASE`、`ET_ACCOUNT_ADMIN_ZONE`，不再复用游戏数据库凭据。要求认证、TLS、副本集。签名目标必须与该固定管理数据库/区服一致。

管理请求先以 majority 写入 AccountAdminAttempt.received，验证后再写 authorized，随后才执行状态事务；无法写前置审计不得执行。非法签名、越权和限流结果写 rejected，不保存签名、公钥、文件路径或原始命令。进入事务后发生异常返回 UNCERTAIN，必须使用原操作 ID 重试核对，不把未知提交结果说成未执行。

进程级管理窗口为滚动 60 秒最多 30 次，包含失败认证，限流在 RSA 验证前执行。进程重启或模型重新加载会重置窗口，不代表跨节点全局限流；全局治理在 017 补充。限流后仍记录拒绝审计；此入口只对具备本机控制台访问权的人员开放，不是公网抗洪泛接口。

管理数据库角色仅具备 Account 的 find/update，以及 AccountStateAudit、AccountAdminAttempt 的 find/insert。不能修改/删除审计，不能删除账号、访问其他集合或创建用户。MongoDB 集合级权限不能限制账号具体字段；管理数据库凭据只能由服务持有，不能交给普通操作人。数据库管理员仍可修改审计，跨故障域不可变副本另行实施。

## 部署与验证

部署管理员先创建 AccountStateAudit、AccountAdminAttempt 集合，再创建上述最小权限角色与专用用户。URI 经 Secret 注入，禁止放入命令参数或仓库。公钥信任表、部署 ID 和签名参数规则仍沿用 016.5。生产游戏服务自身的数据库权限也必须隔离；本项不将当前本机测试的游戏管理级凭据视为生产配置。

测试入口 `Test-AccountAdmin.ps1` 创建仅用于本轮测试的 `et_admin_test_<随机ID>` 用户/角色，使用该身份完成 .NET 签名命令；对随机不存在的探针 ID 尝试禁止操作，要求 MongoDB 返回 Unauthorized，不修改或删除真实审计。最后删除测试身份和私钥，保留测试账号及审计。

前置审计不可写时禁止业务变更；审计库完全不可用时无法持久记录拒绝，仅记录匿名本机告警，不能宣称所有依赖故障下都有持久拒绝记录。后置审计失败时，状态事务审计仍是业务结果的依据；用原 OperationId 重试核对。

## 回滚与遗留

移除管理入口配置可关闭功能。回滚代码不得同时恢复高权限共用凭据，审计集合与已写记录保留。生产账户/Secret 配置、游戏进程最小权限、跨节点限流、跨故障域只追加归档及告警送达仍需后续验收。
