# 018.31 生产逐主机日志转发配置门禁

状态：生产配置生成与 OpenTelemetry Collector Contrib 0.153.0 schema/安全门禁通过；真实跨主机送达、服务托管和后端权限待生产验收。

## 目标

018.24 已验证本机多进程日志解析、脱敏和重启续传，但输出仍是本地证据文件。本项在不绑定具体日志厂商的前提下，生成逐主机 OTLP/HTTP 生产转发配置，保留既有有界读取与脱敏语义，并补充跨网络失败所需的持久发送队列。

## 实现

`New-ProductionLogForwarderConfiguration.ps1` 生成以下固定链路：

`有界 PID 日志目录 → filelog → memory_limiter → 二次脱敏 → batch → OTLP/HTTPS 中心后端`

关键约束：

- 中心端点必须是无 user-info、query、fragment 的绝对 HTTPS URL，并拒绝 localhost/回环 IP；
- 使用 `bearertokenauth` 的 `filename` 读取凭据，配置不嵌入 token；
- filelog 偏移和 exporter `sending_queue` 都使用 `file_storage`，进程重启后可继续读取与发送；
- exporter 失败按 1 秒至 30 秒退避持续重试，持久队列限制为 2048 个请求、两个消费者；
- 输入单条上限 1 MiB、内存上限 256 MiB、批量 128 条，沿用异常多行、severity、correlation ID 和敏感键值二次脱敏；
- 默认只从新日志开始，凭据、配置和状态目录必须位于日志输入目录及仓库外，拒绝重解析路径和覆盖；
- 不启用 OTLP receiver、健康端口或其他网络监听，主机只主动连接中心后端。

认证与 OTLP/HTTP 配置依据上游组件能力：[Bearer Token Authenticator](https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/main/extension/bearertokenauthextension/README.md)、[OTLP HTTP Exporter](https://github.com/open-telemetry/opentelemetry-collector/blob/main/exporter/otlphttpexporter/README.md)。生产固定版本仍以本机/CI 的 0.153.0 二进制验证结果为准。

## 验证

2026-09-13：

- `otelcol-contrib version 0.153.0 validate` 接受完整生产配置；
- 解析配置确认 HTTPS 中心端点、固定资源属性、文件凭据、持久偏移、持久发送队列和无限退避重试均存在；
- 随机 token 内容未出现在配置，且没有任何 receiver 网络监听；
- 明文 HTTP、回环中心、输入目录内配置或凭据、缺失凭据、覆盖已有配置及向仓库写生产配置均被拒绝；

测试时工作区另有未纳入本项的登录代码修改；本项提交只包含生成器、测试、CI 和文档。

## 生产使用边界

配置验证不会连接示例后端，因此 `CrossHostVerified=false`。生产部署必须给每台主机使用独立低权限写入凭据，配置状态目录磁盘告警，实测中心不可用时队列增长、进程重启后补传、队列满时背压，以及中心恢复后的顺序和重复容忍。

文件 bearer token 的轮换按受控配置变更和 Collector 重启执行：先部署新凭据并确认送达，再吊销旧凭据。不能仅替换文件后假定运行中组件已经重新加载。

该链路只转发服务器日志。018.29 客户端体验事件是否上传、采样及用户同意仍取决于客户端遥测方案，不能用服务器日志转发替代。

回滚时应先停止本机 Collector 并保留 `file_storage` 状态；删除状态目录会丢失偏移或待发送队列，属于数据丢弃操作，不是普通配置回滚。
