# 018.27 房间重连处理耗时指标

状态：固定基数指标、单元边界和真实房间断线重连验收通过；客户端公网端到端 RTT 和生产阈值待验收。

## 目标

现有 Gate 登录耗时包含普通登录和房间恢复，无法单独判断 Gate 到 Room 获取重连快照的路径是否变慢。本项只在现有处理耗时体系内补充一条房间重连直方图，不增加协议、动态标签、采集组件或未经生产数据支持的告警阈值。

## 实现

`C2G_LoginGateHandler.CheckRoom` 在等待帧尾、调用 Room 服务、组装重连快照并尝试发送给当前会话的整个服务器侧路径外使用单调时钟计时，并在 `finally` 中记录 `et_room_reconnect_handler_seconds`。成功和异常路径都会留下样本，避免只观察成功请求造成偏差。

直方图沿用 1 ms 至 5 s 的固定桶和 `+Inf`，唯一标签是 Prometheus 直方图固定的 `le`；不包含账号、角色、房间、IP、结果或异常类型，指标基数不会随玩家或房间数量增长。该样本同时仍属于 Gate 登录总耗时，这是有意保留的“整体登录”和“房间恢复子阶段”两个观察视角。

- 固定指标格式和指标总数门禁已同步，新增指标只有固定 `le` 桶标签；
- Release 构建 0 警告、0 错误，26/26 回归通过，健康检查、优雅停机和不安全生产配置拒绝通过；
- 真实玩法场景完成多人匹配开局、首位玩家断线、同账号重新认证和 Gate 登录，验证玩家身份未变化、收到完整房间单位与开始时间快照，并验证重连耗时样本恰好增加一次；
- 同轮套件继续通过服务重启、MongoDB 中断恢复、保存失败停机语义和 20 客户端基线；核心场景证据为 `D:\Program Files\ET\_Env\mongo-local\evidence\gameplay.json`，20 客户端证据为同目录 `gameplay-baseline.json`。

测试时工作区另有未纳入本项的登录代码修改；本项提交只包含房间重连指标、验证和文档。

## 边界与回滚

该指标是 Gate 服务器内部的房间恢复阶段耗时，不包含客户端到 Gate 的公网往返、客户端排队调度、资源加载或首帧可交互时间。当前没有生产流量基线，因此不根据本机验收值设置延迟告警；上线后应结合客户端遥测和真实分位数确定目标。

回滚会删除这一条直方图和对应验收断言，不改变房间重连协议或业务状态。滚动回滚期间监控必须允许旧实例缺少该时间序列，不能把缺失误判为零延迟。
