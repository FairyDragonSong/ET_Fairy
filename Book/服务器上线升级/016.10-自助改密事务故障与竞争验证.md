# 016.10 自助改密事务故障与竞争验证

状态：2026-09-12 本机专项验证通过；不代表多节点或生产故障验收完成。

## 变更

为内部 `UserPasswordStore` 补充账号规范化、密码边界、操作 ID、版本范围和摘要长度检查，避免其他内部调用者绕过协议层的基本输入约束。有效期仍由协议解密层检查。

增加仅内部可调用的事务测试回调，外部请求不能指定。回调为空时生产执行顺序不变：读账号及审计、核对旧密码/版本、更新账号、插入审计、提交事务。

## 验证范围

扩展 `Test-Gameplay.ps1 -SelfCredentials`，使用 `ET_LOCAL_GAMEPLAY` 随机账号：

- 在事务中已执行账号更新、尚未插入审计时注入异常；验证密码仍可用、版本未变、该操作没有审计。
- 两个独立 MongoDB Session 的事务通过测试屏障同时读到版本 0 后竞争改密；必须只有一个成功，另一个冲突，版本仅变为 1，密码属于胜者且只有一条审计。屏障等待上限 10 秒，不能退化为顺序调用测试。
- 已提交操作 ID 配上不同凭据摘要必须拒绝。
- 同时保留 016.9 的真实网络拒绝、改密、重新登录、幂等、限流及旧凭据撤销验收。

测试保留随机竞争账号和审计，不修改真实业务账号，不开放管理权限、不放宽生产启动门禁。

`Test-Phase1.ps1`：Release 编译 0 警告/0 错误，15 项回归、健康/指标/优雅停机及生产配置拒绝通过。`Test-Gameplay.ps1 -SelfCredentials`：新增事务检查及原网络检查均 PASS，正常停机退出码 0。

证据：本机 `_Env/mongo-local/evidence/gameplay-self-credentials.json` 及时间戳报告，新增检查名 `self-password-transaction-rollback-same-version-competition-digest-collision`；报告记录父提交和工作区变更标记。
