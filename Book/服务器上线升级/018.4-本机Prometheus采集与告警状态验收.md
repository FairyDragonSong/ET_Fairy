# 018.4 本机 Prometheus 采集与告警状态验收

状态：2026-09-12 本机功能与带时间戳查询证据验收通过；完整生产监控仍未完成。

## 工具与来源

`Install-LocalPrometheus.ps1` 固定安装官方 Prometheus 3.13.3 Windows amd64 发布包，包含 prometheus/promtool。归档 SHA256 为 `acae8f2d71baab1acac7064a5af29c40ccb9843c1e7e32baa3d5c476ae7978c9`，来自 [官方发布页](https://prometheus.io/download/)；配置依据 [官方配置文档](https://prometheus.io/docs/prometheus/latest/configuration/configuration/)。版本固定而非每次跟随 latest。

安装位置：`D:\Program Files\ET\_Env\prometheus-3.13.3`，包缓存位于 `_Env/downloads`，安装信息单独写入 package.json，不覆盖 MongoDB 包清单。安装不会注册开机服务或自动打开端口。

## 可重复验收

运行 `Tools/ServerOps/Test-LocalMetrics.ps1 -Prometheus`，同时创建两台逻辑目标（同机 RouterManager/Router App 进程）和独立 Prometheus 进程：

- 目标通过各自的回环鉴权端点采集，使用 `authorization.credentials_file`，配置只包含受 ACL 保护的凭据文件路径，不包含 token 明文。
- Prometheus 只监听 `127.0.0.1:30909`，采集和规则评估周期 1 秒。TSDB 使用本轮独立目录，测试保留限制 1 天/128MB；保留限制不是总目录大小的硬上限。
- promtool 校验 JSON/YAML 配置及 `monitoring/et-local.rules.yml` 通过后才启动。
- 查询两个目标 up=1，采集到的 PID 与实际进程对象对应。
- 停止主目标，验证其 up=0、`ETLocalTargetDown` 进入 firing，而另一个目标仍 up=1。
- 重启主目标，验证 up=1、采集 PID 对应重启后的进程，firing 告警序列消失。

规则 `for: 3s`、severity=test 仅供快速本机演练，不是生产 SLO 或值班阈值。当前只是 Prometheus 规则状态，不是已经发出或收到通知；没有 Alertmanager、邮件、企业微信等外部通知配置。

## 证据与运行状态

报告 `_Env/metrics-test-<随机ID>/result.json` 记录父提交、工作区标记、检查清单与 PromQL 查询样本/观察时间。数据库、配置和结果保留；两份临时采集 token 在 finally 删除。测试结束会回收本轮 App 与 Prometheus 进程，因此不会留下常驻采集服务；要重跑请使用上述脚本，保留的旧配置不能在 token 已删除后直接用于采集。

Prometheus 测试进程目前通过精确进程对象结束，而不是验证服务化优雅退出；TSDB 强停恢复也未在本项验收。无生产服务、真实账号或远端监控数据被修改。

本轮结果：官方包哈希和二进制版本验证通过；promtool 配置与 1 条规则校验成功；带 Prometheus 的全部 12 项检查通过，附 10 次成功状态查询的值与时间戳。最终核查测试 App/Prometheus 进程已退出，两份 token 文件不存在。未改动服务器业务代码，本轮不新增业务功能测试结论。

## 后续与回滚

仍需常驻服务部署、受限采集身份与凭据轮换、中央平台认证/远程 TLS、Alertmanager 接收/恢复通知、全栈与跨机器故障演练，以及实际 SLO/容量阈值。Prometheus 回环 UI/API 不带额外身份认证，不应通过无认证代理对外暴露。

本项仅新增工具和测试，不修改业务数据库。停止使用 -Prometheus 即不启动采集器；卸载或清理证据应由独立明确操作处理，不自动删除已有环境或时间序列目录。
