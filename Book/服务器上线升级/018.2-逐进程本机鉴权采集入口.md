# 018.2 逐进程本机鉴权采集入口

状态：2026-09-12 Windows 本机验收通过；生产采集平台、远程安全传输和通知未完成。

## 实现

.NET App 层提供独立指标监听器，不依赖进程是否承载 RouterManager。读取该进程的 OperationalMetrics，不聚合其他进程。默认不监听；显式启用需要同时设置：

- `ET_METRICS_PORT`：1024–65535 之间，每个进程配置不同的空闲端口。
- `ET_METRICS_TOKEN_FILE`：绝对文件路径，内容为密码学随机生成的 32 字节、编码成 64 位十六进制字符串。文件需限制为服务与采集身份可读；不得使用账号密码、管理员密钥或固定示例值。

只绑定 `http://127.0.0.1:<port>/`，不支持通配地址或直接远程访问。只接受 `GET /metrics`，凭据放在 `Authorization: Bearer <token>` 请求头；缺失/错误凭据 401，其他路径或查询串 404，其他方法 405。响应禁止缓存，凭据摘要使用固定时间比较，应用日志不输出请求头或凭据文件路径。密钥在启动时加载，轮换后需重启相应进程。

监听器在 .NET 后台线程中串行处理采集请求，不访问游戏实体。响应写入有界等待，退出时关闭监听并有界等待工作线程结束。配置不完整、端口非法、凭据文件不合法或监听失败会使进程退出码为 3，避免用户以为已启用采集却静默失效。

## 旧入口修复与部署边界

RouterManager 原来使用通配监听，`/metrics` 未检查请求来源。本项将旧 `/metrics` 限制为实际连接来自回环地址，不信任 Forwarded/X-Forwarded-For；远程请求 403，不修改路由业务接口。

旧回环指标路径仍为本机兼容入口，不带新凭据检查。因此本项不是“所有本机指标都必须认证”的保证；同机不可信用户、未经鉴权转发回环入口的代理仍需操作系统和代理隔离。远程采集不得将旧路径直接转发到公网。

推荐部署方向：每台机器由受限本机采集代理读取各进程的回环端口，再经经过验收的 TLS/认证通道送往中央监控。该代理和中央平台尚未部署；此处 HTTP 只用于本机，不替代远程 TLS。Linux、容器网络及非管理员 Windows 服务账号 URLACL/权限尚未实测，不能复制 Everyone 通配授权作为正式部署办法。

## 验证

- `Test-Phase1.ps1`：Release 编译 0 警告/0 错误，16 项回归、旧 HTTP 指标/健康/停机和生产配置门禁通过。
- `Test-LocalMetrics.ps1`：真实 App 进程授权采集成功且响应不含凭据；无凭据、错误凭据、管理路径、查询串及 POST 均拒绝。
- 检查实际监听地址只有 127.0.0.1；通过本机非回环网卡地址请求旧 RouterManager `/metrics`，得到 403。
- 正常停机退出码 0，采集端口释放；不完整/越界端口配置退出码 3；未配置时不监听新端口。
- 结果位于本机 `_Env/metrics-test-<随机ID>/result.json`，包含父提交、工作区标记与检查项。测试凭据放在限制 ACL 的独立目录，finally 精确删除 token 文件，结果文件保留。

本轮未验证多个不同服务进程并发采集、采集代理故障、密钥轮换不中断、慢客户端攻击、Linux 或中央告警。入口由每个 App 进程的主入口初始化，但代码覆盖范围不能替代这些部署验收。

后续 [018.3](018.3-多进程采集隔离验收.md) 已补充 Windows 同机 RouterManager/Router 双进程凭据、计数隔离和单进程停止验证；全栈、跨机器与其他上述边界仍待完成。

## 回滚

同时移除该进程的两个环境变量可禁用新入口；无数据库迁移。若回滚旧路径来源检查，会重新暴露通配监听指标，需提前通过网络策略限制来源。完整 018 仍实施中。
