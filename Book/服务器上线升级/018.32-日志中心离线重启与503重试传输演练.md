# 018.32 日志中心离线、重启与 503 重试传输演练

状态：本机非回环 TLS 真实传输演练通过；双主机网络分区、生产后端和服务托管仍待目标环境验收。

## 目标

018.31 的 Collector `validate` 只能证明配置结构有效，不能证明中心离线、转发进程崩溃后日志仍可发送，也不能证明真实 HTTP 503 会重试。本项对生产配置执行一次有边界的真实传输故障演练，不引入生产 receiver 或修改防火墙。

## 演练流程

`Test-ProductionLogForwarderTransport.ps1`：

1. 选择本机非回环 IPv4 和临时空闲端口，生成只在本轮使用的根 CA 与带该 IP SAN 的服务端证书；
2. 使用 018.31 生成器创建 OTLP/HTTPS、文件 bearer token、持久偏移和持久发送队列配置，并先通过 Collector `validate`；
3. 在中心接收端尚未启动时写入一条无身份测试日志并启动 Collector，等待失败重试状态落盘后强杀 Collector；
4. 启动临时 TLS HTTP 接收端，再用同一配置和状态目录重启 Collector；
5. 接收端第一次返回 HTTP 503，第二次返回 200；验证两个请求体 SHA-256 相同、路径为 `/otlp/v1/logs`、body 非空且存在 bearer Authorization；
6. 精确停止本轮进程并删除临时证书、私钥、token、日志和状态目录。

接收端是该测试脚本的显式 `-Receiver` 子进程模式，只处理两次请求后退出；生产配置仍没有 receiver 或监听器。

## 验证

2026-09-13 最终通过结果：

- Collector：`otelcol-contrib version 0.153.0`；
- TLS 地址：本机非回环 `192.168.1.8`，端口动态分配；
- 中心离线期间 Collector 保持运行并产生持久状态，随后强杀退出；
- 同一状态目录重启后成功建立受临时 CA 验证的 TLS 连接；
- 第一次响应 503、第二次响应 200，请求体哈希一致，认证头存在；
- 报告明确 `CrossHostVerified=false`。

前两次调试失败也未误记为通过：第一次在监听前因 PowerShell 证书扩展方法调用方式错误停止；第二次到达 TLS 握手后发现 Windows SChannel 不支持服务端证书的 ephemeral key，改为不持久保留的当前用户密钥导入方式后独立复验通过。两轮均由 `finally` 回收拥有的进程与临时目录。

Windows CI 在 018.24 本地解析、018.31 配置验证后运行同一传输演练。

## 边界与后续

本项使用同一台机器的非回环网卡，覆盖真实 TLS、HTTP、进程强杀、持久状态和 503 重试，但不覆盖跨交换机路由、防火墙、DNS、真实证书链、代理、双机时钟差、长时间断网或生产后端限流，因此不能把 `CrossHostVerified` 改为 true。

持久状态存在且重启后请求送达，证明该测试日志没有因这次崩溃永久丢失；它不宣称任意队列容量、磁盘满或断电时零丢失。生产故障演练还需观察队列磁盘水位和中心端的可查询记录，并核对保留/访问权限。

回滚只删除测试与 CI 项，不改变 018.31 生成的生产配置。生产环境禁止使用测试证书或测试接收端。
