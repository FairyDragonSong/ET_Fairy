# 018.23 主机与 MongoDB 基础指标门禁

状态：本机真实采集、低基数保留、告警规则和恢复行为门禁完成；生产服务化、跨主机采集和真实值班送达待验收。

## 目标

补齐 ET 进程指标之外的主机和数据库可观测性，避免服务器因 CPU、内存、磁盘、MongoDB 副本集或连接容量故障而只表现为“登录失败”。本项是基础设施监控门禁，不是 2000 在线容量测试，也不重复执行长稳负载。

## 实现

- `Install-LocalInfrastructureExporters.ps1` 将官方固定版本安装到 `D:\Program Files\ET\_Env`，下载物和安装文件均校验固定 SHA-256；安装动作不创建服务、不修改防火墙、不启动监听。
- Windows 使用 `windows_exporter 0.31.7`，仅启用 cpu、memory、logical_disk、net、os、system 收集器。
- MongoDB 使用上游最后提供 Windows 二进制的 `mongodb_exporter 0.47.0`，以随机临时账号、`clusterMonitor@admin + read@local` 最小权限、TLS CA 校验和 SCRAM 认证连接本机三节点副本集。
- MongoDB 用户名和密码通过子进程环境注入，URI 和进程命令行不含凭据；测试结束精确删除临时账号并复查不存在。
- exporter 与 Prometheus 测试监听均绑定 `127.0.0.1`。未授权将无认证 exporter 端口暴露到公网或业务网。
- MongoDB exporter 原始输出约 5049 个指标族，生产采集模板通过 `metric_relabel_configs` 只保留 8 个批准的运维指标族，阻止无边界时序和存储增长。
- `et-infrastructure-scrape.yml` 给出回环采集模板；`et-infrastructure.rules.yml` 提供 exporter 离线、CPU、内存、磁盘、副本成员健康、Primary 数量、复制延迟和连接饱和 9 条告警。
- `Test-InfrastructureMonitoringRules.ps1` 使用固定 Prometheus 3.13.3 的 `promtool` 校验配置、规则以及告警 firing/resolved 行为，并已加入 Windows CI。

## 生产边界与上线前动作

1. Windows exporter 和 MongoDB exporter 必须由 020.21 的受限服务身份托管，并继续绑定回环地址；由同机 Prometheus 或受认证的本机代理转发。不得直接开放 exporter 端口。
2. MongoDB 监控账号必须由外部 Secret 提供层创建和轮换，限制文件/服务 ACL。环境变量避免命令行泄漏，但管理员和同身份进程仍可能读取，不能视为 Secret Manager。
3. 当前 Percona 上游在 0.47.0 后不再发布 Windows 二进制。正式生产不能无期限冻结旧 exporter；上线评审必须选择 Linux 监控节点、内部可复现签名构建，或为固定旧版本建立有时限的风险例外和漏洞响应计划。
4. `ETMongoDBReplicationLag` 以数据承载成员的最大/最小 optime 差计算。若生产副本集包含 arbiter、隐藏成员或延迟副本，必须按拓扑排除非数据承载成员并重新测试，不能直接照搬阈值。
5. 85% CPU、90% 内存、10% 磁盘余量、80% MongoDB 连接利用率和 10 秒复制差是初始工程阈值。版本冻结后的生产同规格长稳与故障演练完成后，再按基线审批调整。
6. 尚需完成生产 Prometheus/Alertmanager 常驻与高可用、跨主机抓取、真实接收人送达、告警静默/升级策略、保留周期和监控存储容量验收。

## 回滚

回滚采集配置时保留上一份已通过 `promtool` 的配置，通过受控 reload 生效并核对所有目标 `up`。卸载 exporter 前先移除对应抓取和告警，避免制造误报；监控账号由数据库管理员精确吊销，禁止删除共享角色或其他账号。回滚不会替代故障调查，业务服务仍须保持自身 `/metrics` 和健康检查。
