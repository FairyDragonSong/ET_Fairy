# 018.3 多进程采集隔离验收

状态：2026-09-12 本机联合验收通过；完整 018 仍实施中。

## 变更

增加 `et_process_id`（操作系统 PID）与 `et_config_process_id`（ET 配置进程号）两个固定名称数值指标，用于核对采集目标。它们不是账号身份，不作为动态指标标签；PID 可复用，不能单独作为跨重启持久标识，应结合现有进程启动时间和采集实例区分。

扩展 `Test-LocalMetrics.ps1`，在同一台 Windows 主机并行运行 Release 配置的进程 8 RouterManager 与进程 9 Router。默认使用独立回环采集端口 30491/30492、独立随机凭据；启动前检查采集与相关业务端口 TCP/UDP 无占用，不修改配置文件或停止已有服务。

## 验收项

- 两个 App 都达到 ready，端点输出的 PID 与实际启动的进程对象相符，ET 配置进程号分别为 8、9。
- 双向交换凭据，必须都返回 401；凭据不跨进程通用。
- 向 RouterManager 的健康入口发请求，其 HTTP 计数增加；Router 进程的 HTTP 计数保持不变，证明不是共享同一份指标快照。
- 停止 RouterManager 后，其采集端口释放；Router 仍能以原凭据采集且 PID 不变。随后正常停止 Router 并确认第二个采集端口也释放。
- 保留旧入口非回环拒绝、错误方法/路径/凭据、默认关闭与非法配置拒绝等已有检查。

所有测试进程均由脚本创建和回收，独立 ACL 目录中的两份临时 token 精确删除，结果文件保留。脚本支持 `-Port`/`-PeerPort`，两个端口必须不同且不能撞到本次服务端口。

本轮结果：`Test-Phase1.ps1` Release 编译 0 警告/0 错误、16 项回归与健康/指标/停机及生产门禁通过；`Test-LocalMetrics.ps1` 全部 9 项检查 PASS，含新增 `two-ready-process-identities-credentials-and-counters-isolated` 和 `one-process-stop-does-not-disrupt-peer-scrape`。带明确双进程 ready 断言的版本已复跑通过。

证据位于本机 `_Env/metrics-test-<随机ID>/result.json`，记录父提交、工作区变更标记和检查清单；无凭据内容。正常停机和 finally 清理后不留下测试 App 进程。

## 边界

这是同机两个真实服务进程的采集隔离与正常停止测试，不是 Realm/Gate/Map 全栈联合压测，也不是跨机器、网络分区、强杀或中央平台故障演练。不能将 HTTP 计数隔离扩展为所有业务状态已实现分布式隔离的证明。

下一步仍包括本机采集代理与中央指标库、采集认证和远程 TLS、告警接收与恢复演练；2000 在线/3000 余量的容量结论仍未得到证明。

无数据库迁移。回滚两个身份指标及脚本扩展即可，不影响账号或角色数据。
