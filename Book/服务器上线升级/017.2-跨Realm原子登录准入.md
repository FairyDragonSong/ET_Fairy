# 017.2 跨 Realm 原子登录准入

状态：本机实现与真实三节点 MongoDB 验收通过；跨主机网络分区和生产 Secret 部署待验收。

## 目标与边界

原登录限流保存在 Realm 进程内。单 Realm 正确，但增加 Realm 后每个实例都有独立额度，攻击者可随实例数量放大尝试次数。本项保留内存限流作为快速挡板，并增加可选的 MongoDB 原子准入作为跨 Realm 总额度。

没有引入 Redis 或新的基础设施。当前登录认证本来就依赖 MongoDB；启用共享准入后，MongoDB 不可用会返回账号服务不可用，不会退回仅本机额度继续放行。

## 实现

- 新增启动参数 `--SharedLoginAdmissionEnabled=1`。未启用时单 Realm 行为保持不变；生产多 Realm 拓扑必须显式启用。
- `ET_LOGIN_ADMISSION_HMAC_KEY_FILE` 提供 32 随机字节的十六进制 HMAC Key。生产文件必须位于受管 Secret 根目录并通过现有租约门禁。
- IP 与规范化账号分别用 HMAC-SHA256 生成不可逆窗口标识，MongoDB 不保存原始 IP、账号或 HMAC Key。
- 文档主键绑定区服、固定窗口、维度和摘要；带 `Count < Limit` 条件的原子 upsert 保证多个 Realm 共享同一额度。
- 首次并发 upsert 的唯一键竞争只有限重试一次；额度已满时唯一键冲突被解释为拒绝，不进行无限重试。
- 使用 majority 写关注；窗口记录带 TTL 索引，在两个窗口后自动过期。
- Watcher 会把开关传给子进程；进程销毁时清零内存中的 HMAC Key。
- 017.1 拓扑工具只有在显式传入 `-SharedLoginAdmissionEnabled` 时才接受同一区服多个 Realm；多 Location 仍然拒绝。

HMAC Key 必须在所有 Realm 上一致。它在 Realm 启动时读取；更换 Key 会形成新的计数空间，因此不能直接做混合 Key 滚动发布。轮换应先停止登录入口、等待当前限流窗口结束、排空 Realm，再统一切换并启动。这一限制不会被描述成无停机轮换能力。

## 验证结果

- Release 编译：0 警告、0 错误。
- 单元测试：29/29，通过维度、窗口和 Key 隔离，确认文档标识不包含原始账号。
- 拓扑策略：未启用共享准入时拒绝多 Realm；显式启用时接受；重复端口和缺失 Location 仍拒绝。
- 真实本机 TLS 三节点 MongoDB：12 个并发请求、账号窗口额度 5，精确得到 5 个接受和 7 个拒绝；TTL 索引存在，持久文档不含测试账号明文。
- 测试证据：`D:\Program Files\ET\_Env\mongo-local\evidence\gameplay-shared-admission.json`。

本次没有证明跨主机网络分区期间的可用性，也没有把 MongoDB 变成无限容量的限流服务。上线前应结合登录峰值测量写负载和延迟。

## 部署与回滚

单 Realm 可继续保持开关关闭。准备多 Realm 时，先在所有实例部署同一受管 Key 和代码，再启用参数并以 `Test-ServerTopology.ps1 -SharedLoginAdmissionEnabled` 验证目标配置。不要在命令行或仓库中放置 Key 内容。

回滚到单 Realm 后可关闭开关；TTL 会自动清理旧窗口。多 Realm 状态下不得关闭共享准入，否则拓扑门禁和运行时策略会拒绝该部署。
