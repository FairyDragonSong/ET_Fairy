# 016.23 恢复审计权限拒绝与真实事务回滚

状态：2026-09-12 真实 MongoDB 审计插入权限拒绝、完整回滚及恢复复验通过。生产授权与持久补偿仍未完成。

## 目的与实现

016.20 在更新后、审计前注入异常，证明了模拟失败回滚；本项进一步让数据库在实际 insert 阶段拒绝恢复审计，验证不会留下没有审计的中断标记。

- 本轮临时角色最初只有恢复审计 find 权限，没有 insert；会话 find/update 权限保持不变。
- 使用该身份执行真实恢复事务，在条件更新完旧记录并检查数量后，审计插入应由 MongoDB 返回 code 13。
- 恢复脚本只捕获明确的 code 13，输出固定阶段 read/update/audit_insert/commit，不输出连接串、账号明细或异常正文；测试必须确认 audit_insert 阶段拒绝。
- 再以只读事务核对原始完整快照和没有该操作的审计，证明所有会话变更回滚。
- 管理连接仅给本轮临时角色补回审计 insert，然后使用受限连接完成正常恢复、模拟回滚、操作冲突及幂等重放。
- 角色更新仅限随机测试身份，结束后仍删除用户/角色并恢复原环境变量。

## 验证边界

原有同账号替换进程持续在线：恢复失败和随后成功都不能改变新实例会话；新实例最后需正常退出且全部记录正常结束。

本项不是任意异常均视为“测试通过”：连接失败、读权限失败、会话更新权限失败及提交阶段失败均不能冒充审计插入拒绝。权限拒绝证据与原始快照回滚证据分别写入报告的 RealAuditPermissionDenied 和 RealAuditDenialRollback。
