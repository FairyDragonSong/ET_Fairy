# 018.24 集中日志采集与重启续传门禁

状态：本机双进程目录采集、结构化转换、脱敏、持久偏移和重启续传验收通过；生产异机日志后端、查询权限与高可用待接入。

## 目标

把 018.17 的逐进程有界文件从“只能登录服务器逐个查看”推进为可集中处理的日志管道，并明确验证关联 ID、异常多行、重启续传、输出保留和暴露面。本项不运行在线玩家压测。

## 实现

- `Install-LocalOpenTelemetryCollector.ps1` 安装固定的 OpenTelemetry Collector Contrib 0.153.0；官方压缩包和解压后二进制均校验固定 SHA-256，安装不注册服务或打开端口。
- `New-CentralLogCollectorConfiguration.ps1` 只有显式传入 `-LocalEvidenceSink` 才生成仓库外 JSON 证据配置，拒绝卷根、重解析点、已有配置/输出以及输出递归落入输入目录；该开关防止把本地 file exporter 误当成生产后端。
- `file_log` 同时读取 `Logs/bounded/<PID>/*.log` 和归档，使用 `file_storage` 保存读取偏移；Collector 重启后从偏移继续，不重放已确认读取的数据。
- 将原有 `时间|级别|logger|消息` 转为 OpenTelemetry 日志，保留原文件路径、logger、级别、部署环境和固定实例标识；异常堆栈等多行消息合并为一条记录。
- 消息中的 `correlation_id=<固定安全字符>` 提取为结构化属性，便于跨 Realm/Gate/Map 查询。没有关联 ID 的日志仍保留，不制造解析错误。
- 对 `password/token/secret/authorization/cookie=value` 做 Collector 侧二次替换；这是纵深保护，不替代源头禁止记录敏感信息，不能保证识别任意自然语言或自定义编码的 Secret。
- 本机证据输出按 64 MiB、7 天、20 个归档设置有界轮转，内存限制 256 MiB，单条输入最大 1 MiB；Collector 管理遥测禁用，不打开监听端口。

## 生产边界

1. 当前 file exporter 是本机可重复验收终点，不是生产“集中存储”，且每次测试代次使用新的输出文件；不能用同一文件配置反复重启来冒充持久后端。上线前需把同一处理管道接到受 TLS、独立凭据和网络策略保护的异机 OpenTelemetry/Loki/OpenSearch 等后端，并验证断网重试、背压、配额和查询。
2. 生产 Collector 必须按 020.21 以受限独立身份托管；输入只读、状态和本机缓冲可写、配置与 Secret 只读，使用 020.20 ACL 门禁。当前临时 ACL 不能替代生产服务账号验证。
3. `event_time` 当前保留为属性，OpenTelemetry 主时间为采集观察时间；在跨时区排序或严格审计前，应统一 ET 时间格式并完成事件时间解析迁移。
4. 只采集 018.17 的 bounded 格式。生产必须显式启用该日志 profile；legacy 文件不能假定可由此解析。
5. 7 天/20 归档只是本机证据保留，不是商业数据保留结论。生产日志期限、访问角色、导出/删除、法务留置和审计查询须与 016 数据治理共同审批。
6. 生产验收仍需多真实 ET 进程、Collector 强杀、后端离线/429/5xx、磁盘满、队列背压、敏感样本和真实值班查询演练；不能以本机 PASS 宣称 018 全部完成。

## 回滚

停止 Collector 前先确认后端已接收至目标偏移并保存状态目录。回滚配置使用新文件且先执行 `otelcol-contrib validate`，不得覆盖活动配置或删除偏移数据库。回滚 Collector 不删除 ET 原始有界日志；若偏移损坏，应在隔离输出中评估重复采集范围，不能直接从 beginning 向生产后端重放全部历史记录。
