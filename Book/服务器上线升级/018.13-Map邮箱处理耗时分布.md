# 018.13 Map 邮箱处理耗时分布

状态：2026-09-12 实现；完整 018 与商业上线验收仍未完成。

## 范围

在 .NET 服务端的 OrderedMessage / UnOrderedMessage 邮箱入口，对所属 SceneType 恰为 Map 的处理记录两个固定直方图：

- `et_map_ordered_mailbox_seconds`：包括进入邮箱后等待 Mailbox 协程锁、有效性检查和等待 MessageDispatcher 返回。
- `et_map_unordered_mailbox_seconds`：等待 MessageDispatcher 返回的耗时，不含有序邮箱锁等待。

使用 Stopwatch 和 finally，正常返回、已进入统计区间后的拒绝/异常均记录；finally 执行前未结束的等待尚未产生样本。已经销毁的 Fiber 在有序入口统计前退出，不计样本。记录的是邮箱调用次数，不是业务成功次数：Dispatcher 内部吞掉/转成 RPC 错误的异常不会自动成为独立失败标签。

沿用固定 12 桶（含 +Inf）、count/sum 和线程安全更新，单位秒。唯一标签为 le，无消息类型、账号、Unit、房间或正文标签。采集前捕获 SceneType，结束时不再次访问可能销毁的实体。

这不包含 Fiber 投递队列中等待、网络 RTT、客户端耗时，或处理函数另起且未等待的协程。不覆盖 Gate Session 入口、其他 SceneType、绕过这两类邮箱的调用或所有未来业务。本项使用 DOTNET 条件编译，不为 Unity 客户端启用服务端指标。
