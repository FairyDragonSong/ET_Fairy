# 018.30 生产逐主机指标转发配置门禁

状态：生产配置生成与 Prometheus 3.13.3 schema/安全门禁通过；真实跨主机写入、服务托管和中心高可用待生产验收。

## 目标

现有 ET、Windows 和 MongoDB 指标都只在回环地址暴露，这是正确的最小暴露面，但生产中心监控不能直接跨网抓取这些入口。本项提供逐主机 Prometheus 转发配置：只抓本机回环目标，再通过 HTTPS `remote_write` 发往中心端点，不开放新的游戏主机指标监听地址。

## 实现

`New-ProductionMetricsRelayConfiguration.ps1` 根据主机角色选择 ET、windows_exporter 和 mongodb_exporter 本地目标：

- ET 指标必须使用独立 bearer token 文件；
- 中心 `remote_write` 使用另一份 bearer token 文件，禁止与本机抓取凭据使用同一路径或同一内容；
- 中心地址必须是无 user-info、query、fragment 的绝对 HTTPS URL，并拒绝 localhost/回环 IP；
- 所有抓取目标固定为 `127.0.0.1`，端口必须互不冲突；
- 固定 `host_id` 和 `deployment` 外部标签用于中心侧按部署和主机隔离，不写玩家或业务动态标签；
- 可选私有 CA 文件，最低 TLS 版本为 1.2；默认系统信任库仍可用于公有 CA；
- 配置只引用凭据路径，不读取后嵌入 token；输出必须位于仓库外、拒绝重解析路径及覆盖已有文件。

生成器不替操作者启动 Prometheus、不修改防火墙、不安装服务，也不会探测或写入生产中心，避免配置阶段产生未经授权的外部变更。

## 验证

2026-09-13：

- 使用已固定安装的 Prometheus/promtool 3.13.3 验证包含 ET、Windows、MongoDB 三个本机抓取任务和中心 remote_write 的配置，schema 通过；
- 解析生成文件确认三个目标均为 `127.0.0.1`，外部标签与中心地址正确，两个随机 token 的内容均未出现在配置；
- 明文 HTTP、回环中心端点、共用凭据、重复端口、空目标集合、覆盖现有配置及向仓库写生产配置均被拒绝；
- 测试仅使用临时目录，结束时校验路径后精确递归清理；
- Windows CI 复用供应链固定的 promtool 执行同一门禁。

测试时工作区另有未纳入本项的登录代码修改；本项提交只包含生成器、测试、CI 和文档。

## 生产使用边界

每台主机应使用独立 `host_id`，并由部署系统提供只读本机抓取凭据和只允许写入对应租户/部署的中心凭据。生成后仍需以专用低权限服务身份运行 Prometheus agent/relay，限制 WAL 磁盘预算，验证断网缓存、恢复补传、凭据轮换和中心拒绝时的行为。

本机 schema 通过不等于 `CrossHostVerified=true`。只有在预发布或生产等价的两台以上主机上确认中心收到全部目标、标签未串区、网络中断后恢复、旧凭据失效且告警仍能送达，才能关闭跨主机指标部署项。

回滚本项只删除生成器和对应配置；不会改变 ET 指标端点或业务服务。已经部署的 relay 必须先由运维停止并保留 WAL，再按变更流程回滚，不能通过删除 WAL 掩盖未发送样本。
