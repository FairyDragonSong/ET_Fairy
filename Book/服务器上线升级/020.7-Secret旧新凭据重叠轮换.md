# 020.7 Secret 旧新凭据重叠轮换

状态：密码 Key Ring、KeyId 选择与指标双 Token 动态重载已通过本机真实链路验证；生产 Secret Manager 轮换、客户端公钥发布和多实例顺序待验收。

## 背景与目标

020.6 只支持单个密码私钥和启动时载入的指标 Token。直接覆盖会使旧客户端的在途改密信封无法解密，指标采集切换也需要重启。本项提供有界的旧新凭据重叠窗口，同时拒绝未知 KeyId、无限堆积历史密钥和互相冲突的来源。

## 密码解密 Key Ring

生产可继续使用单文件 `ET_ACCOUNT_PASSWORD_PRIVATE_KEY_FILE`，或切换为 `ET_ACCOUNT_PASSWORD_KEYRING_FILE`，两者必须且只能配置一个。Key Ring 是 `ET_SECRET_ROOT` 下的受限 JSON Secret，不属于普通配置，格式如下：

```json
{
  "SchemaVersion": 1,
  "ActiveKeyId": "password-current",
  "LegacyKeyId": "password-previous",
  "Keys": [
    { "KeyId": "password-previous", "PrivateKeyPem": "<Secret Manager 注入>", "NotBefore": 0, "NotAfter": 0 },
    { "KeyId": "password-current", "PrivateKeyPem": "<Secret Manager 注入>", "NotBefore": 0, "NotAfter": 0 }
  ]
}
```

实际时间必须为 Unix 秒且覆盖当前时间；示例中的 0 不能用于部署。KeyId 只允许 3–64 位 ASCII 字母、数字、点、下划线和连字符；最多 4 把密钥，ID 唯一，每把都必须是有效 RSA-4096 以上私钥。`ActiveKeyId` 必须存在；可选的 `LegacyKeyId` 把没有 KeyId 的旧客户端/旧管理命令映射到旧密钥。

改密信封新增可选 `KeyId`，并把它加入 AES-GCM 关联数据，篡改 ID 即使错误地复用了同一 RSA 密钥也无法通过认证。客户端使用可信发布的公钥和对应 KeyId 加密，Gate 先验证 KeyId 格式，再从每次请求重新读取的 Key Ring 精确选择私钥；未知、过期或已移除 ID 返回原有脱敏失败，不提供密钥枚举信息。管理密码重置命令增加可选 `PasswordKeyId`，签名覆盖该字段；生成脚本用 `-PasswordEncryptionKeyId` 明确选择公钥版本。

推荐轮换顺序：

1. 在 Key Ring 加入新密钥，保留旧密钥并让 `LegacyKeyId` 指向旧密钥；先部署所有 Gate。
2. 通过已签名客户端配置发布新公钥与 KeyId，确认新信封已出现并可解密。
3. 等待最长 5 分钟信封有效期、重试窗口和最低客户端版本生效，再移除旧密钥与 `LegacyKeyId`。
4. 吊销并安全销毁旧私钥，保存不含密钥内容的轮换审计。

新客户端在旧 Gate 上会因额外 KeyId 字段被拒绝，因此必须先升级全部 Gate，再发布使用 KeyId 的客户端；当前项目尚未完成 017 混合版本滚动发布，不得反向操作。

## 指标 Token 动态轮换

`ET_METRICS_TOKEN_FILE` 是当前 Token；轮换期间可增加 `ET_METRICS_PREVIOUS_TOKEN_FILE`。启动时两者都必须是不同的 64 位十六进制随机值。指标服务在每次 scrape 时从受管 Secret 文件重新读取并以固定时间摘要比较，因此可不重启进程完成：先把旧当前值写入 previous 文件，再原子替换 current 文件为新值，切换采集器，确认成功后在下次部署移除 previous 配置。

文件短暂缺失、格式错误或逃逸 Secret 根目录时请求返回未授权，不沿用不可审计的陈旧缓存。两个 Token 只扩大到轮换期，不能长期并存。端点仍只监听 `127.0.0.1`，错误请求不会把 Token 写入日志。

## 安全、部署与回滚

Key Ring 让一个文件暂时包含多把私钥，读取权限必须比普通配置更严格；最多 4 把和有效期校验用于限制无界遗留，但生产平台仍需告警过期与超期重叠。KeyId 不是秘密也不是授权凭据，不能替代 TLS、客户端签名配置或私钥保护。

Secret 文件更新必须使用同目录临时文件、完整写入、限制 ACL 后再原子替换，禁止原地逐字节覆盖。生产需记录发起人、审批、旧新 KeyId、部署实例、验证与吊销时间，不记录 PEM、Token 或数据库 URI。

若新密钥失败，在旧密钥仍位于重叠窗口时把 ActiveKeyId 和客户端公钥配置退回旧 KeyId；不得恢复已确认泄漏的私钥。协议代码回滚前必须停止发布带 KeyId 的客户端。数据库字段没有变化；已经成功的密码修改和审计不回滚。

## 遗留问题

- 尚未在生产 Secret Manager/KMS、Windows 服务账号 ACL 和多实例 Gate 上执行轮换演练。
- Key Ring 当前保存可导出的 PEM 私钥，不等同 HSM/KMS 不可导出密钥；后续若接入 KMS，应把解密操作迁移到提供方 API。
- 指标双 Token 是本地端点凭据轮换，不包含 Prometheus/代理之间的远程 mTLS 证书轮换。
