# 018.20 地图传送终态指标与失败恢复

状态：代码、故障注入和本机真实传送验证通过；跨主机故障与公网客户端体验待验收。

## 目标

Gate 的 `G2C_EnterMap` 为保证消息顺序，会在帧尾异步执行真实 Unit 传送。因此响应成功只表示请求已受理，不证明 Map 服务已经收到玩家。旧实现没有传送终态指标，并且传送抛出异常后仍保留 `Player.MapEntered=true`，后续请求会一直被当成重复进入而拒绝。本项同时关闭观测和恢复缺口。

## 实现

- `et_map_entry_attempts_total`：Gate 收到的地图进入请求。
- `et_map_entry_rejections_total`：Session 已失效或同一玩家重复进入。
- `et_map_entry_service_errors_total`：临时场景、Unit 或目标 Map 配置在受理前初始化失败。
- `et_map_entry_accepted_total`：临时 Unit 已建立且异步传送已经排入执行。
- `et_map_transfers_inflight`：已受理但尚未得到传送终态的数量。
- `et_map_transfer_successes_total`、`et_map_transfer_failures_total`：`TransferAtFrameFinish` 的真实完成结果。

受理与完成计数在锁内维护，完成时必须存在对应在途传送，防止重复终态造成负数。传送异常继续向协程基础设施抛出并保留原错误，同时恢复 `MapEntered=false`、移除本次精确 `GateMapComponent` 及其临时 Scene，使当前在线会话可以重新发起进入。受理前异常使用相同的精确组件检查清理，不会删除后来创建的其他实例。

## 验证

- 指标回归并发执行 1000 个拒绝、1000 个受理前服务错误和 1000 个成功传送，另保留一个在途及一个失败终态，逐项核对计数；无在途任务的重复完成必须失败。
- `Test-Gameplay.ps1 -SelfCredentials` 使用可控传送函数先抛出异常，验证失败数增加、在途归零、临时组件删除且 `MapEntered=false`；随后在同一 Player 上重试成功，验证成功/失败各一个且没有重复终态。
- 完整真实玩法链路核对进入请求受理后，只有 Map RPC 已可用才接受传送成功计数；重复进入只增加拒绝计数，不污染服务故障。
- Release 编译、26 项第一阶段回归、健康/指标/优雅停机和生产配置失败关闭继续作为提交门禁。

## SLI 与边界

服务端地图传送 SLI 可按窗口计算 `transfer_success / (transfer_success + transfer_failure)`；同时监控在途数量及最长处理时间，避免只看已完成样本而遗漏悬挂任务。进程被强杀时内存中的在途 gauge 会随进程消失，必须结合 `up`、进程启动时间和会话遗留记录判断，不能当成自然恢复。

传送成功表示 Map 端处理返回成功，但仍不证明客户端已经收齐切场景和 Unit 消息。公网 DNS、TLS、代理、丢包、客户端加载和渲染需要客户端遥测或入口层数据补齐。当前故障注入验证状态机清理，不伪装成跨主机网络分区测试。

## 回滚

回滚进入处理器和指标即可，无数据库或协议迁移。回滚会重新引入传送失败后无法重试及终态不可见问题；依赖新指标的查询和告警必须先停用。
