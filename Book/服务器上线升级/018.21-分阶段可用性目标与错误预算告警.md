# 018.21 分阶段可用性目标与错误预算告警

状态：规则、Runbook、本机 promtool 行为测试与 CI 门禁完成；最终业务签署、生产采集和外部通知待验收。

## 目标

018.18–018.20 已能区分 Realm、Gate 和 Map 传送的成功、业务拒绝与服务故障。本项将三个阶段归一为可执行的 Prometheus SLI，建立多窗口错误预算告警、最低样本量、传送卡死检测和处置说明，避免只有指标却没有可行动告警。

## 工程目标与规则

当前采用内部可用性 99.5% 作为预发布工程基线，不是合同 SLA。每个阶段分别计算 `success / (success + service_error)`；错密码、限流、失效 Key 和重复进入等拒绝不消耗服务可用性预算，但仍由独立安全/产品指标观察。

规则通过六个 recording rules 将原始计数归一到固定 `stage=realm|gate|map-transfer`，不携带账号、角色、IP、Token 或错误文本：

- Fast burn（critical）：5 分钟错误率超过 7%、1 小时超过 3%，且 5 分钟至少 20 个终态，持续 5 分钟。
- Slow burn（warning）：30 分钟错误率超过 3%、6 小时超过 1%，且 30 分钟至少 100 个终态，持续 15 分钟。
- Map transfer stuck（warning）：任一采集范围的地图传送在途总量持续非零超过 2 分钟。

Fast/slow 组合防止一次低样本失败立即升级为事故，也能发现持续消耗。生产多区服时必须按部署/区服的外部采集标签隔离路由；本文件不从业务请求注入动态标签。

## 自动化验证

- `promtool check rules` 校验 9 条 recording/alerting rules。
- `promtool test rules` 注入持续 Realm 服务故障，验证 Fast burn 进入 firing，停止错误增长后恢复为空；另验证地图在途持续两分钟 firing、归零后 resolved。
- `Test-ProductionSloRules.ps1` 强制检查三阶段原始指标、告警、目标和 Runbook 引用，拒绝身份或凭据标签。
- GitHub Windows 基线流水线安装已锁定 SHA-256 的 Prometheus 3.13.3，再执行相同规则测试，不依赖开发机已有文件。

本机实际结果：promtool 3.13.3，9 条规则语法通过，两组行为测试通过。

## 运维与上线边界

告警统一引用 [登录与地图 SLI 告警处置](运维模板/登录与地图SLI告警处置.md)，要求核对 `up`、进程启动时间、部署代次、阶段依赖、拒绝流量和 resolved 通知。计数器重启归零不能被当成故障恢复。

当前没有生产监控集群、正式值班名单和外部企业微信/电话渠道，99.5% 也尚未由业务负责人签署；因此 018 仍为实施中。正式上线前需用 2000 在线长稳流量校准最低样本量和阈值，完成多实例聚合、监控自身高可用、通知送达和真实故障演练。

## 回滚

先停用引用这些 recording rules 的告警，再回滚规则、测试和文档。删除业务指标不是本项回滚内容。回滚后不得以“没有 firing 规则”解释为服务健康。
