# 020.8 网络暴露面与入口防护门禁

状态：本机代码与开发模式行为验证通过；生产 URL ACL、TLS 入口、防火墙和 DDoS 服务待目标环境验收，不可据此批准正式上线。

## 目标与完成边界

减少 RouterManager、Router UDP/TCP 和 Router WebSocket 的误暴露面，让生产模式对通配监听、公开内网链路和未声明的公网 Router 失败关闭；同时给管理 HTTP 与 WebSocket 建立请求边界和过载保护。

本项完成的是应用代码门禁、Windows URL ACL 迁移工具和本机行为验证。TLS/WSS 终止、云防火墙、安全组、四层 DDoS 清洗、七层限速/WAF 和实际服务账号 ACL 都依赖最终部署平台；未取得这些证据前，本项保持“生产待验收”。

## 应用网络契约

生产模式 `--Develop=0` 使用以下环境配置：

| 配置 | 要求 |
| --- | --- |
| `ET_ROUTER_MANAGER_BIND_IP` | 必填且只能是显式回环 IP，例如 `127.0.0.1`；明文 HTTP 只供同机 TLS 入口代理访问。 |
| `ET_ROUTER_WEBSOCKET_BIND_IP` | 启用 `--RouterWebSocket=1` 时必填且只能是显式回环 IP；客户端只能通过入口代理提供的 WSS 访问。 |
| `ET_ROUTER_PUBLIC_EXPOSURE_ACK` | Router UDP/TCP 使用非回环 OuterIP 时必须精确设置为 `firewall-ddos-rate-limit-v1`。它只是部署方确认，不是防火墙或 DDoS 已配置的证据。 |

生产 Router 的 OuterIP 不允许 `0.0.0.0`/`::`，InnerIP 只允许回环、RFC1918 IPv4、链路本地或 ULA IPv6。开发模式未配置上述绑定变量时继续兼容原有通配监听，因此开发配置不得复制到生产。

RouterManager 启动后会检查 `HttpListener.IsListening`；WebSocket Router 同样检查监听结果。组件 Awake 内部异常不再可能让这两个入口被误报为已启动。

## 入口请求边界

RouterManager HTTP：

- 只接受无查询字符串、无请求体的 GET；错误方法返回 405 并声明 `Allow: GET`，查询或请求体返回 400。
- ET Router 客户端不再给 `/get_router` 拼接随机 `?v=`；响应已经使用 `Cache-Control: no-store`，无需以违反服务端契约的查询参数破坏缓存。真实 Router Realm/Gate/Map 链路纳入回归。
- 最多处理 256 个在途请求，超过后返回 503；该端点只承担健康、指标和 RouterManager 查询，不承载玩家长连接。
- 响应增加请求 ID、`no-store`、`nosniff`、禁止页面内容与来源泄漏的安全头。

Router WebSocket：

- 只接受精确 `/et/` 路径、GET、无查询参数且确为 WebSocket Upgrade 的请求。
- `--RouterWebSocketMaxConnections` 默认 4096，合法范围 1–100000；达到上限返回 503。
- 监听日志只记录 host、port 和 path，不再用 `0.0.0.0` 文案掩盖真实绑定。

这些进程内限制是最后一道保护，不替代入口代理的单 IP/账号限流、最大连接年龄、握手超时、报文大小、带宽配额和 DDoS 清洗。

## Windows URL ACL 迁移

`Set-ServerHttpUrlAcl.ps1` 的 Audit 为只读；Apply 要求管理员 PowerShell、显式服务身份和精确 URL 二次确认。它先为回环地址和服务账号建立精确保留，成功后才移除相同端口和路径的 `*`/`+` 保留；精确保留创建失败时不会删除原保留，删除通配项失败时则保留已建立的精确项并以失败退出，等待人工核对。

提升权限后，以实际 ET Windows 服务账号执行（示例身份必须替换）：

```powershell
.\Tools\ServerOps\Set-ServerHttpUrlAcl.ps1 -Action Apply -Port 30300 -Path '/' `
  -ServiceIdentity '<ET服务账号>' -ConfirmUrl 'http://127.0.0.1:30300/'

.\Tools\ServerOps\Set-ServerHttpUrlAcl.ps1 -Action Apply -Port 31301 -Path '/et/' `
  -ServiceIdentity '<ET服务账号>' -ConfirmUrl 'http://127.0.0.1:31301/et/'
```

每个实际启用的 Router WebSocket 端口均须独立执行并审计；当前 Release 示例可能涉及 31301–31304，不能为未启用端口预留 `Everyone`。服务身份不是当前交互式个人账号，除非该账号确实就是经批准的服务身份。

## 验证记录

- `Test-Phase1.ps1`：Release 构建 0 警告/0 错误；24/24 回归通过；开发模式 RouterManager 的存活、就绪、指标、安全响应头、POST 405、查询参数 400 和优雅停机通过；不安全生产配置继续失败关闭。
- 网络策略单元测试：生产缺少绑定、通配绑定、公开 InnerIP、未确认公网 Router 均拒绝；回环管理/WebSocket 和私网 InnerIP 通过。
- 源码防回退：覆盖精确绑定、监听结果、HTTP 请求边界、WebSocket 路径/Upgrade/连接上限以及 URL ACL 迁移保护。
- PowerShell 脚本全量语法解析通过。
- 本机 URL ACL 只读审计：30300 目标精确保留不存在且发现 `http://*:30300/`；31301 `/et/` 目标精确保留不存在且发现 `http://+:31301/et/`；两项退出码均为 2。
- 曾尝试建立 30300 精确保留，Windows 在删除旧保留前以错误 5 拒绝，确认需要提升权限；旧系统状态未被更改。生产精确监听因此没有伪报为已验证，开发 HTTP 冒烟显式使用 `--Develop=1`。

## 上线验收与回滚

目标主机必须在变更窗口内完成：备份现有 URL ACL 输出；以服务账号迁移并使 Audit 退出 0；确认非服务账号无法直接访问回环端点；从公网只能访问经批准的 TLS/WSS 域名；扫描确认管理端口、MongoDB 和 InnerIP 不可公网到达；验证防火墙/DDoS/限流规则及告警；执行正常流量、过载、错误路径和回滚测试并归档证据。

回滚应用代码不会自动还原操作系统 URL ACL。URL ACL 回滚必须依据变更前备份并经审批执行，不能盲目恢复 `Everyone` 通配项。入口代理回滚到旧版本时仍应保持 TLS 和访问控制，不得绕过代理临时暴露明文端口。

- 需要公网 UDP/KCP 时，确认平台能提供适用的四层防护；仅有 HTTP WAF 不保护 UDP。
