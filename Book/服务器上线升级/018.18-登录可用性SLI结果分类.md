# 018.18 登录可用性 SLI 结果分类

状态：2026-09-12 代码与本机自动化验证通过；生产 SLO、窗口和告警阈值待确认。

## 目标

原有 `et_login_failures_total` 同时累计错密码、输入错误、限流、账号状态拒绝、数据库不可用和 Gate RPC 故障。直接用它计算登录可用性会把用户错误或攻击流量算成服务故障，也无法说明服务器是否履约。本项在保留兼容总数的同时建立互斥的低基数结果分类。

## 实现

- `et_login_rejections_total`：密码或输入不正确、账号状态拒绝、登录限流等由调用方或策略导致的失败。
- `et_login_service_errors_total`：账号存储不可用、Gate Key RPC 失败及处理器未记录结果前抛出的异常。
- `et_login_failures_total` 在同一次指标快照中由上述两个计数相加，避免并发采集时总数与分类短暂不一致。
- 成功、总失败和两个分类均声明为 Prometheus counter；不增加账号、IP、错误码或其他动态标签。
- Realm 处理器使用 `outcomeRecorded` 防止已记录拒绝或服务故障后又被异常路径重复计数。成功请求仍只进入 `et_login_successes_total`。

建议的服务端登录可用性 SLI 分母仅使用成功与服务故障：`success / (success + service_error)`。拒绝数单独用于认证攻击、产品输入问题和限流容量分析。正式查询应使用 Prometheus 时间窗口增量，并设置最小样本量；不能直接拿进程启动以来的累计值作告警。

## 验证

- `Test-Phase1.ps1` 覆盖两类计数各 1000 次并发写入、总数相等、类型元数据、非法枚举拒绝和固定指标序列。
- 源码架构回归约束账号存储故障、Gate RPC 故障、用户拒绝及未处理异常的分类调用点，防止后续把所有失败重新合并。
- `Test-Gameplay.ps1 -SelfCredentials` 通过真实 Realm 账号密码请求确认错密码只增加拒绝计数、不增加服务故障计数；原有改密、撤销、会话记录和 3000 条结束记录专项同时通过。
- Release 编译必须保持 0 警告、0 错误；完整运行冒烟验证健康、指标和优雅停机接口仍可用。

## 边界与后续

本项只保证 SLI 的事件分类基础，不替项目承诺 99.9% 等数值。生产 SLO 必须结合真实流量、2000 在线长稳测试、维护窗口和业务承诺确定，并由正式 Prometheus/告警平台验证多进程聚合、进程重启、无流量窗口、最小样本量、快速/慢速燃尽告警与恢复通知。

Gate 登录阶段目前有独立延迟直方图，但尚未建立同等精度的 Gate 结果分类；因此本指标描述 Realm 获取 Gate Key 的可用性，不代表端到端进入地图成功率。客户端网络超时也需要在入口或客户端遥测层另行观测。

## 回滚

回滚两个分类计数及 Realm 调用点即可，不涉及协议、数据库或数据迁移。回滚会恢复无法区分用户拒绝与服务器故障的旧指标，生产 SLO 查询在回滚前必须先停用，避免产生错误结论。
