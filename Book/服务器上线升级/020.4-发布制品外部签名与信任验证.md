# 020.4 发布制品外部签名与信任验证

状态：签名机制与本机一次性密钥验收通过；生产签名身份、密钥托管、吊销和发布端信任配置待部署。

## 目标与实现

在 020.3 的逐文件清单和 ZIP 哈希之外，为发布归档增加可由独立信任锚验证的签名。`New-ServerRelease.ps1` 当前默认必须同时接收仓库外的 PKCS#8 PEM 私钥文件和受限格式 Key ID；缺少其中任一项、私钥位于仓库内或 RSA 小于 3072 位均失败。只有显式 `-AllowUnsignedTestArtifact` 才能生成标记为未签名的兼容测试包，不能误作默认发布路径。

构建器生成 UTF-8 无 BOM 的 `*.attestation.json`，包含产品、版本、源提交、ZIP 文件名/哈希、ZIP 内 manifest 哈希、Key ID、签名算法和 UTC 时间，再使用 RSA-PSS/SHA-256 生成二进制 `*.attestation.sig`。签名绑定 ZIP 哈希，ZIP 又绑定 manifest 和全部运行文件，因此不是只给可替换的 `.sha256` 文本签名。

`Test-ServerRelease.ps1` 默认要求显式受信 SubjectPublicKeyInfo PEM 与预期 Key ID；验证 RSA-PSS 签名、密钥至少 3072 位、版本/文件名、源提交、签名时间格式、ZIP/manifest 哈希以及 manifest 的版本和提交一致性，之后才解压和逐文件验证。只有显式 `-AllowUnsignedTestArtifact` 能检查 020.3 的历史未签名测试包。

CI 为每次测试在 runner 临时目录生成一次性 3072 位密钥，构建签名包并以对应公钥执行干净来源、完整性和运行冒烟，finally 删除两个测试 PEM。该密钥只证明签名代码闭环，不构成生产信任；工作流不输出私钥正文、不上传测试包。

## 生产边界

正式上线仍需选择生产信任体系：推荐在受保护 CI/OIDC 工作负载身份中调用 KMS/HSM 完成签名，发布主机只持有固定公钥/证书链，并定义 Key ID 轮换、旧版本验证窗口、密钥吊销、双人审批、签名审计和泄漏应急。把 PEM 私钥放到普通 CI Secret 虽好于入库，仍不等价于不可导出的 HSM 密钥。

验证命令接收的公钥本身必须通过可信配置分发并由操作系统权限保护；若攻击者能同时替换包和传入公钥，签名无法提供信任。当前未连接真实 KMS、未配置发布服务器信任存储，也未做代码签名证书/可信时间戳，因此 020 正式发布门禁仍未完成。

## 回滚

发布端可在明确迁移窗口内用 `-AllowUnsignedTestArtifact` 检查旧测试包，但生产策略不应回退为接受未签名包。密钥轮换应并行信任新旧公钥至旧版本窗口结束，再移除旧 Key ID；私钥疑似泄漏时立即吊销对应 Key ID、停止发布并重新签名可信源码产物，不靠重写 attestation 修复。
