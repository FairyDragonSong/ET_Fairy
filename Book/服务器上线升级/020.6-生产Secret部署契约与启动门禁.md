# 020.6 生产 Secret 部署契约与启动门禁

状态：本机代码、失败关闭和回归验证通过；生产 Secret Manager、Windows 服务身份 ACL 与无停机轮换仍待部署验收。

## 背景与目标

020.4 解决发布制品签名，但运行时数据库连接、密码信封私钥、指标 Token 和运营管理信任仍可能因路径错误、弱密钥或残缺配置而带病启动。本项建立统一的生产 Secret 文件边界，并在对应能力开始服务前失败关闭；不生成、不提交、也不替换真实生产凭据。

## 部署契约

- `ET_SECRET_ROOT` 必须是绝对路径、已存在、位于应用二进制目录之外且自身不是符号链接/重解析点。所有生产 Secret 文件必须位于其下，中间目录和文件也不能经过链接跳转。
- Linux/macOS Secret 文件不允许 group/other 读取、写入或执行；Windows 运行时只验证路径与内容，服务身份 ACL 仍须由部署平台单独审计。
- 生产密码登录启用时，`ET_ACCOUNT_PASSWORD_PRIVATE_KEY_FILE` 必填，必须是 Secret 根目录内不超过 16 KiB 的可解密 RSA 私钥且至少 4096 位。仅有公钥、弱密钥、缺失文件或逃逸路径均拒绝启动。
- 指标端口和 `ET_METRICS_TOKEN_FILE` 必须同时配置；Token 必须是 32 个随机字节的 64 位十六进制编码，并继续只监听 loopback。
- 任一账号管理变量出现时，信任文件、数据库、Zone、DeploymentId 与管理 MongoDB URI 必须完整配置。管理 URI 可由 `ET_ACCOUNT_ADMIN_MONGO_URI` 注入，或推荐通过 `ET_ACCOUNT_ADMIN_MONGO_URI_FILE` 从 Secret 根目录读取，二者不能同时使用；URI 必须为认证、校验证书的 TLS Replica Set。
- 管理信任文件启动时验证非空、操作人 ID 唯一、未过期、作用域完整且仅含 RSA-3072 以上公钥；私钥进入信任文件会被拒绝。
- 游戏 MongoDB 新增 `ET_MONGO_URI_FILE` 和按区的 `ET_MONGO_URI_FILE_ZONE_n`。文件方式与原 `ET_MONGO_URI` / `ET_MONGO_URI_ZONE_n` 同层级互斥，按区配置继续优先于共享配置。原环境变量方式保留，以兼容能安全注入环境变量的 Secret Manager。

正式密码服务器至少需要由部署系统注入如下“路径”，内容本身不得写入启动脚本：

```text
ET_SECRET_ROOT=<应用目录外的受限 Secret 挂载目录>
ET_MONGO_URI_FILE=<Secret 根目录内的游戏库 URI 文件>
ET_ACCOUNT_PASSWORD_PRIVATE_KEY_FILE=<Secret 根目录内的 RSA-4096 PKCS#8 私钥>
```

## 代码变更

- `ProductionSecretPolicy` 集中执行路径包含关系、链接、文件大小、Unix 权限、密钥强度、Token 格式、管理信任与管理库 TLS 拓扑校验。
- `Program` 在加载命令行配置后、进入服务器更新循环前检查本进程已配置的指标、管理和密码 Secret；失败仅输出固定错误，不打印路径、连接串、PEM 或具体凭据内容，并以退出码 3 结束。密码登录私钥的“必须存在”校验放在 Gate 初始化且早于会话数据库初始化，避免纯 Router/Map 进程也被迫挂载解密私钥。
- 指标服务、自助改密和账号管理执行时再次通过同一受管文件读取器读取 Secret，降低只在启动时检查而实际使用绕过策略的风险。
- 数据库解析器支持游戏 MongoDB URI 文件注入，并拒绝同一层级同时配置明文环境变量和文件来源。
- 账号管理支持管理库 URI 文件，现有直接环境变量方式兼容保留。

## 安全与兼容边界

本项不会把 Secret 加密后放入 Git；加密文件和解密密钥若一同入库仍等同明文泄漏。`ET_SECRET_ROOT` 是路径边界，不是 Secret Manager，也不能替代主机加固、进程隔离和操作系统 ACL。

生产密码登录相比之前更严格：承载 Gate 的进程缺少 RSA-4096 私钥时拒绝完成启动，而不是只让改密请求运行时失败；不承载该能力的进程无需取得私钥。部署时应先挂载 Secret，再启动新版本。后续 [020.7](020.7-Secret旧新凭据重叠轮换.md) 已增加密码 Key Ring/KeyId 与指标双 Token 动态重载；生产 Secret Manager、多实例顺序和客户端公钥发布仍需实际演练，不能仅凭本机测试宣称生产无停机轮换。

## 部署与回滚

先在 Secret Manager 创建独立于制品的挂载，限制到 ET 服务身份读取，再以非敏感环境变量传入根目录和文件路径；预检通过后启动。禁止在命令行参数、GitHub Actions 日志或服务日志打印文件内容。

回滚应用前必须确认旧版本是否支持 `*_FILE` 变量；不支持时由 Secret Manager 临时改回安全的进程环境注入，不得复制到仓库配置。代码回滚不删除 Secret，不撤销密钥；若因疑似泄漏回滚，仍必须在凭据平台完成吊销和轮换。

## 遗留问题

- 在目标 Windows/Linux 主机上验证服务账号 ACL、Secret Manager 挂载、审计日志和凭据吊销，当前本机测试不能替代。
- 020.7 已实现 KeyId 与旧新双读窗口；仍需在生产 Secret Manager 和多实例上完成轮换演练。
- MongoDB 应使用最小权限账号并在数据库侧验证轮换；文件注入只解决交付方式，不证明数据库角色最小化。
