# 020.3 发布产物清单与完整性验证

状态：本机构建、完整性、运行冒烟和失败分支通过；CI 托管运行、制品签名与正式发布待验收。

## 目标与实现

`New-ServerRelease.ps1` 从干净 Git 工作树和固定提交生成版本化 Windows x64、依赖 .NET 8 Runtime 的服务器 ZIP。版本名只能是受限 SemVer；输出版本目录已存在时拒绝覆盖。构建使用锁文件恢复，App 用 `dotnet publish` 输出到全新暂存目录，Hotfix DLL/PDB 单独构建进入同一 Bin，避免复用长期 Bin 中已删除的 EPPlus 等陈旧文件。

产物只包含运行 Bin，以及服务端需要的 `Config/Excel/s`、`Config/Recast`、NLog legacy/bounded 配置。未包含客户端配置、源码、Logs、数据库连接、测试环境 Secret 或整个工作区。Hotfix.pdb 当前是 `CodeLoader` 的必需输入，因此保留；其他 PDB 是否发布后续按崩溃诊断与源码保护策略评审。

ZIP 内 `manifest.json` 记录模式版本、产品/版本、40 位源提交、工作树是否脏、UTC 构建时间、平台、运行时要求、启动工作目录，以及每个文件的相对路径、长度和 SHA-256。ZIP 外同名 `.sha256` 校验整个归档。`Test-ServerRelease.ps1` 拒绝多个归档、多余文件、名称/校验格式错误、ZIP 哈希不符、清单路径穿越或重复、遗漏/多出文件、长度/文件哈希不符及关键运行文件缺失；可要求干净来源并从解压后的 Bin 启动健康检查、发送 shutdown、验证退出 0。

CI 在基础回归通过后生成 `0.0.0-ci-<run id>` 到 runner 临时目录，以 `-RequireCleanProvenance -RuntimeSmoke` 验证。工作流不自动上传、部署或推送产物，避免未经审批的二进制成为正式版本。

## 安全边界与剩余

SHA-256 能发现传输损坏和相对既定清单的篡改，但同目录的 ZIP、清单和 SHA 文件可被有写权限者一起替换，**不等于数字签名、可信时间戳或供应链证明**。正式上线还需受保护 CI 身份签名、不可变制品库、审批与保留策略，并验证发布机器只接受受信签名。当前包是 Windows x64 框架依赖产物，不宣称 Linux、容器或自包含兼容。

清单中的 Git 提交只能证明声明来源；CI 外部 Action、NuGet 包和构建主机信任仍由 020.1/020.2 及后续签名/SBOM 子项闭环。配置文件本身不含 Secret，生产 URI、证书私钥与监控 Token 必须在部署时由独立 Secret 系统注入。

## 回滚

发布目录不可覆盖；回滚选择上一个已验证并受信的完整版本，不在服务器上拼接新旧 DLL。当前仅生成临时测试产物，未部署、不修改数据库。若构建脚本回滚，不影响已运行服务器或数据，但会失去产物白名单和完整性门禁。
