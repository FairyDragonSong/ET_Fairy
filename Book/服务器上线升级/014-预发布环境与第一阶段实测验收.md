## 背景与目标

001–013 已通过仓库内编译、进程内回归与 RouterManager 冒烟，但当前开发机没有 MongoDB、Database Tools、容器运行时或预发布连接，尚未验证真实 Replica Set 事务、故障切换、隔离恢复和负载容量。本项必须形成可重复执行的预发布验收闭环，且不把“脚本存在”误标为“生产环境已通过”。

## 设计决定

- `Test-Preproduction.ps1` 作为统一入口，拒绝无认证、无显式 TLS、弱化证书/主机名校验、单机拓扑、关闭 `retryWrites` 或脏工作区。
- 源库和恢复库必须不同；恢复库名称必须以 `_DR_TEST` 结尾并精确二次确认，降低误覆盖风险。
- MongoDB 脚本验证真实认证会话、Replica Set/分片拓扑、必需索引、事务提交与主动回滚。
- 备份后恢复到隔离数据库，比较 Account、Role、Schema 文档数量并再次执行关联一致性检查。
- 自动生成不含 URI 和凭据的 JSON 证据；备份与证据目录默认不进入 Git。
- 切主、网络故障、多客户端和压测具有部署平台相关性，必须在真实环境单独留证，统一脚本不会虚构结果。

## 安全与数据影响

- 源数据库仅执行审计和带唯一随机标记的事务探针，探针最终清理。
- 恢复步骤会删除并覆盖指定的隔离恢复库内容，因此要求独立库名、固定后缀和精确确认。
- URI 只从 `ET_MONGO_URI` 读取，不写入报告、参数示例中的真实值或 Git。
- 证据包含提交哈希、数据库逻辑名、计数与结果，不包含用户数据、密码或 Token。

## 验证结果

已完成：

- PowerShell AST 与 JavaScript 静态语法检查。
- 安全失败路径：当前无 `ET_MONGO_URI` 时入口立即拒绝，不产生数据库或文件变更。
- 仓库 `git diff --check`。

等待真实预发布环境执行：

- 统一入口的事务、索引、审计、备份、隔离恢复与证据生成。
- MongoDB 主节点切换、短时断网、进程崩溃与恢复。
- 登录、重复登录、普通地图/房间重连、Gate Key 重放与过期的多客户端实测。
- 登录吞吐、目标在线量、消息延迟、错误率及资源水位压测。

因此本项当前不能标记“已完成”，也不能据此批准商业上线。

## 部署与回滚

本次只增加验收工具，不改变服务器运行行为。回滚可删除新增脚本和文档；脚本运行后如需清理隔离恢复库，应由 DBA 在再次确认库名和证据保留要求后执行，不由仓库脚本自动删除。
