# 020.10 签名紧急停服与优雅排空

状态：签名命令、启动前门禁和运行中优雅排空已在本机真实进程验证；生产信任部署、文件 ACL、恢复审批和多进程控制器待验收。

## 目标与威胁边界

为安全事件、错误发布和运营事故提供不依赖公开管理端口的紧急停服入口。停服文件不是“看到文件就杀进程”：命令必须由受信 RSA-PSS 身份签名，并绑定部署、操作、原因和有效期。合法命令在开网前阻止新进程启动；运行中的进程发现命令后复用现有停接入、会话结束记录、有限并发角色保存和超时退出流程。

本项不实现恢复授权或 Windows 服务重启策略。停止标记持续存在时，即使命令过期或信任变更，新进程也会因命令无效而失败关闭；恢复必须先经过事故负责人审批，再由具备目录 ACL 的部署控制器移除标记。当前仅靠操作系统 ACL 控制删除，签名恢复命令和 A/B 监督进程属于下一子项。

## 配置契约

启用时三个变量必须同时存在：

| 环境变量 | 要求 |
| --- | --- |
| `ET_EMERGENCY_STOP_FILE` | 停服命令绝对路径；父目录必须已存在；生产路径必须位于应用目录外。文件正常运行时可以不存在。 |
| `ET_EMERGENCY_STOP_TRUST_FILE` | JSON 信任表绝对路径；生产模式必须位于 `ET_SECRET_ROOT` 下并满足现有受管文件/链接/权限规则。 |
| `ET_DEPLOYMENT_ID` | 3–80 位字母、数字、点、下划线或连字符；命令和信任身份必须精确匹配。 |

信任表是 1–4 个条目的数组，每项包含 `KeyId`、RSA-3072 以上公钥、DeploymentId、NotBefore 和 NotAfter。Key ID 必须唯一，所有条目必须属于当前部署且尚未过期，并至少有一把当前有效密钥；最多允许提前 24 小时挂入下一把轮换公钥。信任表在启动时校验，运行时每次发现停服文件都会重新读取，支持受控轮换。

紧急停服目前是可选能力，以免破坏开发模式和尚未完成 020 部署的旧环境。商业生产清单必须把上述配置设为必填；未部署受保护信任表和命令目录时，不能把本项标记为生产验收完成。

## 签名命令

`New-EmergencyStopCommand.ps1` 要求：仓库外 RSA-3072 以上私钥、受限 Key ID、DeploymentId、ReasonCode、精确的 `ConfirmDeploymentId`、5–1440 分钟有效期，以及仓库外绝对输出路径。目标已存在时拒绝覆盖；先写同目录随机临时文件，再原子移动到目标路径。

签名 Payload 包含 SchemaVersion、固定动作 `stop`、DeploymentId、32 位随机 OperationId、ReasonCode、IssuedAt 和 ExpiresAt。运行时限制签名命令最长 24 小时、未来签发时钟偏差 5 分钟，并以 RSA-PSS/SHA-256 验签。日志只记录操作 ID 和受限原因码，不输出 Payload、签名或公钥正文。

示例（占位值必须替换）：

```powershell
.\Tools\ServerOps\New-EmergencyStopCommand.ps1 `
  -PrivateKeyFile 'D:\Protected\EmergencyStop\operator.private.pem' `
  -KeyId 'incident-primary' -DeploymentId 'prod-cn-1' `
  -ReasonCode 'security-incident' -ValidMinutes 60 `
  -ConfirmDeploymentId 'prod-cn-1' `
  -OutputFile 'D:\ET-Control\prod-cn-1\emergency-stop.json'
```

私钥不得放在 ET 服务器、仓库或命令目录。推荐由独立事故响应身份在隔离管理机/KMS 中签名，再通过受审计渠道原子投放命令。

## 运行行为与退出码

- 启动阶段发现合法命令：不执行服务器 Update，不创建 RouterManager/Realm/Gate 网络入口，退出码 4。
- 启动阶段配置不完整、信任无效、命令损坏/伪造/跨部署：失败关闭，退出码 3。
- 运行阶段发现合法命令：`ShutdownReason.EmergencyStop` 单向锁定，后续普通 shutdown 不能降级原因；各 Scene 完成排空且成功后退出码 4。
- 运行阶段命令验证失败：按紧急事件请求排空，不继续忽略可疑控制文件；排空成功退出 4。
- 排空存在会话记录或角色保存失败：保留原优先级更高的失败退出码 2，部署控制器不得自动重启或晋级。

指标新增 `et_shutdown_emergency`，配合 `et_shutdown_requested`、会话记录和角色保存失败计数区分普通维护与紧急停服。

## 安全、兼容与回滚

新增环境变量未配置时保持旧运行行为；启用时任何部分配置都拒绝启动。退出码 4 是新的受控停服语义，现有服务管理器若配置了“任何非零都重启”，必须先修改策略，否则会形成停服—重启循环；退出码 2/3/4 都应停止自动晋级并告警。

回滚代码不会移除外部停服标记。若回滚到不识别该标记的旧二进制，旧版本可能重新开网，因此事故期间禁止回滚到 020.10 之前的服务器；A/B 部署控制器必须先识别全局停服状态，再决定能否启动任何槽位。

文件签名阻止伪造授权，但不能阻止有目录写权限者删除命令造成未授权恢复，也不能替代服务账号 ACL、独立信任分发、双人审批、KMS 审计和主机入侵响应。
