# 016.24 签名账号数据导出与完整性审计

状态：2026-09-13 本机真实 MongoDB 链路通过；生产身份、保留策略和用户自助申请流程待验收。

## 目标与边界

在不新增公网管理端口的前提下，为客服或隐私请求提供受控账号数据导出。导出复用 016 的短时 RSA-PSS 签名命令、操作员动作授权、部署/数据库/区服绑定、账号 ID 二次确认、预期版本和管理限流。

本项只实现 `export`，不实施物理删除。物理删除涉及登录身份、角色、会话、审计保留和法定义务冲突，必须单独设计审批、冷静期、备份过期与不可变审计边界，不能与普通导出共用一次操作。

## 实现

- `account-admin` 新增独立 `export` 动作；未在操作员信任表中授予该动作时拒绝执行。
- 仅允许写入服务器配置的绝对 `ET_ACCOUNT_EXPORT_ROOT`。目录必须预先存在，拒绝磁盘根目录和重解析点；生产模式拒绝应用目录内路径。
- 导出账号基础资料、关联角色、会话历史和账号状态历史。明确排除密码哈希、盐、算法参数、加密密码、凭据摘要、私钥、Token，以及进程、Gate 和启动实例拓扑字段。
- 每类关联记录最多 10000 条，超过上限失败关闭，不生成不完整且被误认为完整的文件。
- 文件名固定为签名命令的 `OperationId.json`，调用方不能提交任意输出路径。文件使用 `CreateNew` 和原子移动，拒绝覆盖已有文件。
- `ET.Server.AccountDataRequestAudit` 记录操作、账号、预期版本、操作人、原因、固定输出文件名和 SHA-256。相同操作重试必须同时通过命令一致性、文件存在性和摘要校验才返回幂等成功。
- 数据库写入确认丢失时会以 majority 读核验审计；无法确认时保留文件并返回不确定，不会删除调用前已经存在的同名文件。
- 生产启动配置检测到 `export` 权限时要求导出根目录同时配置，避免上线后首个请求才暴露缺项。

数据库身份仅需以下权限：账号、角色、会话和账号状态审计的 `find`，数据请求审计及管理尝试审计的 `find/insert`。不需要账号或角色更新/删除权限，也不能读取无关集合。

## 本机验收

- `dotnet build DotNet/DotNet.sln -c Release --nologo`：0 警告、0 错误。
- `dotnet run --project DotNet/Tests/DotNet.Tests.csproj -c Release --no-restore`：27/27 通过；覆盖 `export` 动作授权和输出根目录边界。
- `Tools/ServerOps/Test-AccountDataExport.ps1`：在本机 TLS/认证三节点副本集创建隔离账号和临时只读导出身份，验证：
  - 只可读取批准集合，账号/角色更新和删除、审计删除及无关集合读取均被 MongoDB 拒绝；
  - 篡改签名不生成文件；
  - 有效命令导出一份标准可解析 JSON，包含账号、角色和会话；
  - 文件不存在密码或凭据字段及 Gate 内部拓扑字段；
  - 同一命令重复执行不生成第二份文件；
  - 数据请求审计唯一，保存的 SHA-256 与文件一致。
- 首轮权限验收因测试脚本未捕获 MongoDB code 13 异常而误判，临时身份已清理；修正后确认越权被正确拒绝。
- 第二轮因单元素信任表被 PowerShell 展开为对象而在授权阶段正确拒绝，未生成导出；改为数组后通过。
- 第三轮暴露 MongoDB 默认 `NumberLong(...)` 不是标准 JSON；改为 Relaxed Extended JSON 后最终链路通过。失败过程保留为实现记录，不冒充一次通过。

所有测试账号均位于 `ET_LOCAL_GAMEPLAY`，临时数据库身份在 `finally` 删除；测试导出仅含本轮合成账号数据，保留在本机受限验收目录作为证据。

## 生产待办与回滚

生产接入仍需确定导出文件 ACL、静态加密、交付渠道、自动过期清理、访问留痕、请求人身份核验和目标发行地区的隐私期限。没有这些制度与真实权限证据前，本项不能宣称完整合规。

回滚代码会移除 `export` 动作，不删除既有导出文件或审计记录。既有文件应按已批准的保留流程处置，不能由回滚脚本自动清理。
