## 背景与目标

升级 002 已让账号数据进入 MongoDB，但 Gate 的 `PlayerId` 仍是每次首次进入进程时随机生成，角色地图和位置也没有加载、定时保存或下线保存。本项把认证账号与默认角色绑定，并形成以下闭环：

```text
账号认证 → Gate 加载/创建默认角色 → 使用稳定 RoleId 创建 Player
        → 按角色地图与位置创建 Unit → Map 周期保存
        → Session 断线触发最终保存 → 成功后卸载 Unit 和 Gate Player
```

## 设计决定

- 一个账号在第一阶段拥有一个 `DefaultRoleId`；多角色选择后续按业务需求扩展。
- `Role.Id` 同时作为 Gate `Player.Id` 和 Map `Unit.Id`，跨登录保持稳定。
- Role 保存地图名、位置、创建时间、最近登录时间和最近保存时间。
- Map 每 60 秒保存在线角色；断线时再次保存，成功后移除 Unit Location 和内存 Unit。
- Gate 在普通地图玩家断线 30 秒后卸载 Player；30 秒内重连会取消卸载。锁步房间中的玩家保留原有房间重连策略。
- 如果下线保存失败，Map 保留 Unit 供周期任务重试，不用删除内存状态换取表面上的“下线成功”。

## 代码与配置变更

- `Account` 新增 `DefaultRoleId`，新增 MongoDB `Role` 模型及角色仓储。
- Gate 首次登录时加载或创建默认角色，并以稳定的 `RoleId` 创建 `Player`。
- 进入地图时恢复上次地图和坐标，地图切换不再重置坐标。
- Map Unit 增加 60 秒周期保存；断线时最多重试三次最终保存。
- `G2M_SessionDisconnect` 升级为 Location RPC。Map 只有保存成功才移除 Unit，并向 Gate 确认；保存失败时 Gate 与 Map 都保留状态。
- Gate 普通地图玩家在保存确认后保留 30 秒，期间重连会取消卸载；超时后清理 GateSession 和 Player Location。
- Gate、锁步 Map 增加分区数据库组件，为角色读写提供连接。

## 安全与数据影响

- 角色创建与 `Account.DefaultRoleId` 更新使用账号协程锁串行化。
- 当前跨集合写入采用失败补偿；真正的唯一索引和迁移版本在 005 完成。
- 日志记录 RoleId、账号和保存错误，不记录认证凭据。

## 部署与回滚

本项新增 Role 集合和 Account 字段。MongoDB 忽略旧文档缺失字段，旧账号会在下一次 Gate 登录时创建默认角色。回滚前应保留数据库备份；旧代码会忽略新增字段和 Role 集合。
