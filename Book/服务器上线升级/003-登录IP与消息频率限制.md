## 背景与目标

密码认证使用高成本 PBKDF2。如果攻击者可以无限调用登录接口，会直接消耗 Realm CPU。已连接客户端如果可以无限发送小消息或大流量，也会消耗反序列化、分发和内存资源。

本项在两个尽量靠前的位置建立保护：

- Realm 执行密码哈希前，按来源 IP 和规范化账号限制登录请求。
- 外网 Session 反序列化前，按连接限制每秒消息数和字节数，超限立即断开。

## 设计决定

采用进程内固定窗口计数器，避免为第一阶段引入 Redis 依赖。默认参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `LoginIpLimit` | 30 | 单 IP 每个登录窗口最大请求数 |
| `LoginAccountLimit` | 10 | 单账号每个登录窗口最大请求数 |
| `LoginRateWindowSeconds` | 60 | 登录固定窗口秒数 |
| `OuterMessageLimit` | 100 | 单外网 Session 每秒最大消息数 |
| `OuterBytesLimit` | 262144 | 单外网 Session 每秒最大数据字节数 |

登录名只有在通过格式规范化后才进入账号计数表，任意超长或非法输入只按 IP 计数，避免攻击者制造大量字典 Key。计数表定期清理过期窗口。

该实现保护单个 Realm/Gate 进程，不替代云防火墙、负载均衡、WAF/DDoS 清洗或多节点共享限流。

## 安全与数据影响

- 限流日志只记录 IP、规范化账号和重试时间，不记录密码或凭据。
- 登录限流失败统一返回业务错误，不执行数据库查询和 PBKDF2。
- 外网 Session 超限直接断开，避免继续解析消息。
- 参数小于 1 时运行时按 1 处理，防止误配置完全关闭保护。

## 验证结果

- `dotnet build DotNet/DotNet.sln -c Release --no-restore`：0 个警告、0 个错误。
- `dotnet build Unity/Unity.Editor.csproj --no-restore`：0 个错误、12 个既有 LitJson 目标框架警告。
- 已检查登录调用顺序：IP/账号限流位于 MongoDB 查询和 PBKDF2 之前。
- 已检查外网消息顺序：Session 计数位于消息反序列化和分发之前；超限路径先回收 `MemoryBuffer` 再销毁 Session。
- 已检查无 Session 的异常读包路径，现在也会回收 `MemoryBuffer`，避免缓冲区泄漏。
- 尚未执行真实网络突发流量测试；具体边界、窗口重置和并发攻击场景纳入升级项 008。

## 部署与回滚

所有参数都有默认值，旧启动命令兼容。Watcher 会转发显式配置。回滚不涉及数据库变更。
