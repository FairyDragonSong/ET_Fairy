# 018.9 角色保存成功与失败耗时

状态：2026-09-12 实现、单测和本机数据库中断恢复验收通过；完整 018 仍实施中。

## 口径

在 `RoleRepository.SaveProgress` 统一入口计时，新增 `et_role_save_success_seconds` 与 `et_role_save_failure_seconds` 两组直方图。覆盖调用此入口的周期保存和下线/停机最终进度保存，不包含账号注册、角色创建事务、备份或任意 MongoDB 命令。

计时从 SaveProgress 进入至 finally，包含查询旧角色、更新字段、数据库保存和失败处理。只有数据库 Save 返回后才归为成功；角色不存在、查询/保存抛异常或其他失败归入失败组。失败样本不能证明磁盘上完全没有写入——未知提交结果仍需通过数据证据确认。

沿用固定累计桶（1ms 至 5s，加 +Inf）、秒单位、微秒整数累计和文化无关格式。成功/失败使用两个固定名称而非账号/错误文本标签，慢失败不会混在成功组中掩盖正常写入延迟。

旧 `et_role_save_successes_total` / `et_role_save_failures_total` 的周期保存调用点保持不变，不能假定其绝对值等于新直方图 count：新组覆盖所有 SaveProgress 调用，范围更大。

## 验证

单测增加两种结果独立计数、失败总耗时检查，保留桶边界、并发更新、非法输入和固定标签检查。`Test-Phase1.ps1`：Release 编译 0 警告/0 错误，17 项回归及健康/指标/停机与生产配置门禁通过。

扩展既有 `Test-Gameplay.ps1 -Outage`：真实本机 MongoDB 副本集暂停后，周期保存必须观察到失败；数据库恢复后保存必须成功，最终要求两组耗时 count 都大于 0。沿用隔离的 `ET_LOCAL_GAMEPLAY` 随机账号，不修改生产服务或凭据。

本轮 `role-save-latency-outage-failure-and-restored-success`、`database-outage-map-kept-and-service-recovered`、`periodic-save-failed-then-recovered` 均 PASS。测试副本集约 95 秒不可用后恢复一主两从，游戏链路与保存恢复；并未放宽会话租约或写关注。

证据位于本机 `_Env/mongo-local/evidence/gameplay-outage.json` 及时间戳报告，包含父提交和工作区变更标记。不将同机副本集强停测试扩展为跨机器网络分区或生产存储性能结论。

## 边界与回滚

这不是数据库命令级追踪，也不是磁盘 fsync 延迟或备份恢复耗时。尚未覆盖查询/更新分段延迟、连接池等待、所有 MongoDB 操作、跨机器写关注延迟，以及 2000/3000 在线下的存储容量。

函数未返回、进程强杀或正在等待的调用不会提前生成完成耗时样本。生产告警阈值仍需基线数据；本项不增加写入重试、不调整写关注或放宽登录/租约安全门禁。

没有数据库迁移或协议变更；回滚采样代码与测试即可，不删除角色、备份或历史指标。
