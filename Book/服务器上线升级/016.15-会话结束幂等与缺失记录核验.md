# 016.15 会话结束幂等与缺失记录核验

状态：2026-09-12 实施未命中更新的终态核验；真实数据库验证结果见下方。可靠补偿与强杀恢复仍未完成。

## 问题

原 EndCore 只要 MongoDB 更新命令不抛异常就返回 true，即使 ModifiedCount=0。这样既可能是安全的重复结束，也可能是记录缺失或未知状态，不能作为补偿成功的依据。016.14 的事后全量核对能发现部分问题，但正常服务端排空也必须正确判定。

## 实现

- 正常 admitted → ended 条件更新与 majority 写入不变，成功修改一条才增加 JournalEnded。
- 未修改记录时，在同一个 3 秒操作时限内执行 majority 读取，按 _id 核验已有状态。
- 只有存在 State=ended、日期类型 EndedAtUtc、Int32 类型 DisconnectError 的终态记录，才按幂等成功处理；不重复增加 JournalEnded，也不覆盖原结束时间或错误码。
- 缺失记录和不完整/非法终态分别记录固定 reason=missing_record / invalid_terminal，增加失败计数，由已有队列使 Drain 失败。
- 不 upsert、不自动创造结束记录、不修改旧证据；不打印账号、记录 ID 或异常正文。

本项终态检查不是全字段审计，例如不在这里重新核对历史账号版本；正常基线仍由 016.14 全量核对。新读取使用 Gate 已有 find 权限，不新增数据库角色。

## 验证

在隔离 ET_LOCAL_GAMEPLAY 的 SessionJournalBurst 专项中追加：

1. 对已结束记录用不同错误码重复结束，比较完整文档保持不变，成功计数不重复增加。
2. 对随机不存在的 ID 执行结束，验证队列失败、Drain=false，数据库没有自动新增文档。
3. 插入本轮专用的缺少结束证据的 ended 测试记录，验证失败且原文档未被覆盖；核对失败计数恰好增加两次。
4. 原 3000 条集中结束、队列溢出及数据库写入权限拒绝测试继续保留。
