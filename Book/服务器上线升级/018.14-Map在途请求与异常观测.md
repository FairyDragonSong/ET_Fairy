# 018.14 Map 在途请求与异常观测

状态：2026-09-12 实现；完整 018 与商业上线门禁仍未完成。

## 指标与语义

新增四个固定名称、无动态标签的指标：

- `et_map_ordered_mailbox_inflight` / `et_map_unordered_mailbox_inflight`：已进入统计区间、尚未退出的邮箱调用数。有序入口包含等待 Mailbox 锁的调用。
- `et_map_ordered_mailbox_exceptions_total` / `et_map_unordered_mailbox_exceptions_total`：从邮箱处理区间向外抛出的异常累计数。

进入时递增，finally 中递减；catch 仅标记并原样重新抛出。一次调用捕获同一 OperationalMetrics 实例，避免完成时取到不同实例。方法内部使用 Interlocked，调用者必须配对 Start/Finish，本项不增加自动容错钳零掩盖不配对错误。

异常计数**不是业务失败率**：处理器内部捕获并转换为 RPC Error 的失败、正常返回的拒绝不一定向邮箱抛出异常，因此不计入 exceptions。无序调用很短时 gauge 可能始终被采到零，累计异常/耗时样本仍可增长。

沿用 018.13 的 .NET / Map / 两类邮箱边界，不含尚未出队的消息、其他 SceneType、客户端 RTT 或另起后台协程。inflight 不为每个玩家去重，也不提供单个请求详情；进程重启后重新计数。它与完成后才记录的 histogram 是互补关系，采集并非所有字段的原子事务快照。

## 验证设计

单测包含 1000 次并发有序 Start/Finish、无序未完成时 gauge=1、异常完成后 gauge=0 与异常分类计数，保留固定基数检查。

SelfCredentials 的隔离测试新增 Map 子场景和真实邮箱处理入口调用：持有实际 Mailbox 锁 150ms，确认等待未完成、gauge 增加且 histogram count 不变；释放后以不属于 Actor Dispatcher 的空 Ping 消息触发受控缺失处理器异常，确认原异常传递、gauge 回到基线、耗时 count 和异常计数增加。无序分发也验证异常清理。

此测试不新增外网消息或生产接口；测试函数仍受 Develop=1 / ET_LOCAL_GAMEPLAY 门禁保护。两个邮箱内部 awaitable 方法由 private 改为 internal 供同一 Hotfix 程序集验证，正常 Invoke 路径不变。受控异常不是业务 RPC Error、网络超时或所有异常路径的验收。
