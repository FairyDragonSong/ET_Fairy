## 停机流程

```text
Ctrl+C / SIGTERM / `shutdown` 控制台命令 → 标记 shutdown requested
  → Realm/Gate 停止外部网络入口
  → Map 遍历在线角色并最多重试三次保存
  → 所有参与 Scene 报告完成 → 释放 World 并退出 0
  → 超时或保存失败 → 退出 2，交由运维告警处理
```

默认排水上限为 15 秒，可用 `--ShutdownTimeoutSeconds` 调整。排水开始后 `/health/ready` 返回 503，`et_shutdown_requested` 变为 1。`SIGKILL`、断电和运行时崩溃无法执行优雅停机，因此 004 的周期保存与 005 的备份恢复仍然是必要的数据安全层。

## 安全与边界

- 进程信号只设置线程安全标记；实体访问和保存仍在各自 Fiber 内执行。
- Map 保存失败不会伪装成成功，进程以非零状态退出。
- Realm/Gate 先移除外部网络组件，阻止排水期间接收新登录。
- Location、Match 等当前没有业务落库任务的进程直接释放 World；后续新增持久化组件时必须注册为停机参与者。

- `git diff --check`：通过。
- 当前环境没有启动 MongoDB 与在线角色，Map 批量保存、保存失败退出码 2 的真实故障注入由 008 集成测试覆盖。

## 回滚

回滚进程循环、协调器、Scene 停机组件和对应配置项即可。回滚后部署系统不应再依赖退出码 2 判断排水失败。
