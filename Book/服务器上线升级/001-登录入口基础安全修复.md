# 001-登录入口基础安全修复

## 基本信息

| 项目 | 内容 |
| --- | --- |
| 状态 | 已完成 |
| 实施日期 | 2026-08-23 |
| 目标阶段 | 第一阶段 |
| 影响范围 | Unity 客户端、Gate 登录入口 |

## 背景与目标

升级前存在两个直接风险：

- 登录界面在密码输入变化时把完整明文密码写入客户端日志。
- Realm 签发的 Gate 登录 Key 在有效期内只查询、不删除，可能被重复提交。

本次升级目标是消除密码日志，并把 Gate 登录 Key 改成一次性消费。它是账号认证建设前的入口加固，不代表账号密码已经得到服务器验证。

## 设计决定

Gate 登录 Key 使用 `Take` 语义：第一次提交时查询并立即删除，后续流程即使失败，同一个 Key 也不能再次使用。Gate Scene 运行在单个 Fiber 执行上下文内，查询和删除不会被另一个 Gate 消息并行插入。

Key 仍保留原有 20 秒超时清理。Key 已被消费后，超时协程再次删除不存在的 Key 是安全的。

## 代码与配置变更

| 文件 | 变更 |
| --- | --- |
| `LoginPanelComponentSystem.cs` | 删除包含完整密码内容的 Info 日志，密码仍只保存到当前登录面板组件中供登录请求使用。 |
| `GateSessionKeyComponentSystem.cs` | 使用 `Take` 替代可重复读取的 `Get`，读取成功后立即删除 Key。 |
| `C2G_LoginGateHandler.cs` | Gate 登录改为消费一次性 Key。 |

协议结构和起服配置没有变化，旧客户端不需要更新消息格式。

## 安全与数据影响

- 新产生的客户端日志不再记录用户输入的完整密码。
- 同一个 Gate Key 只能成功取出一次，降低有效期内的重放风险。
- 本次变更不会清理升级前已经存在的历史日志，发布或测试环境应按实际情况安全删除旧日志。
- 当前 Realm 登录仍未验证 `C2R_Login.Password`，账号密码认证将在升级项 002 中实现。
- 当前传输层尚未为 KCP 登录数据提供端到端加密，这不在本项范围内。

## 验证结果

- 已检查 Gate Key 的项目内调用点，业务登录入口已经切换为 `Take`，没有遗留对旧 `Get`/`Remove` 接口的调用。
- 已执行 `dotnet build DotNet/DotNet.sln -c Release --no-restore`，结果为 0 个警告、0 个错误。
- 已执行 `dotnet build Unity/Unity.HotfixView.csproj --no-restore`，结果为 0 个错误、17 个既有依赖/API 警告；警告来自 LitJson 目标框架版本和 YooAsset 已弃用 API，与本次修改无关。
- 本次没有启动 Unity Editor，客户端界面登录和 F6 热更新编译回归尚未执行。
- 尚未执行客户端到 Realm、Gate 的运行时重复 Key 集成测试；该场景将纳入升级项 008。

## 部署与回滚

该变更不修改协议或持久化数据，可以随客户端 HotfixView 和服务器 Hotfix 一起部署。服务端升级后，重复发送同一个 Gate Key 会返回 `ERR_ConnectGateKeyError`，属于预期行为。

如需回滚，可恢复 Gate Key 的查询接口和 Handler 调用；不建议恢复密码明文日志。
