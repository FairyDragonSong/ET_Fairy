# 018.29 客户端登录与入图体验事件

状态：客户端顶层登录和入图体验耗时事件已实现并通过 .NET 编译与固定字段回归；生产汇聚和真实设备网络基线待验收。

## 目标

服务器处理耗时不能反映客户端路由连接、网络往返、场景切换和界面事件处理。本项在现有客户端顶层流程补充两个低频、固定字段的体验事件，不新增上传协议、账号标识或客户端可写的服务端业务指标。

## 实现

- `LoginHelper.Login`：从替换 `ClientSenderComponent` 前开始，经过 Realm/Gate 登录，直到所有 `LoginFinish` 异步订阅处理完成；
- `EnterMapHelper.EnterMapAsync`：从发出入图 RPC 前开始，经过服务端响应和 `Wait_SceneChangeFinish`，直到发布 `EnterMapFinish`。

两个入口都用单调时钟并在 `finally` 中记录，因此成功和抛出/捕获的失败都会产生终态事件。固定格式为：

`CLIENT_EXPERIENCE stage=<login|enter_map> outcome=<success|failure> duration_ms=<invariant decimal>`

事件不含账号、密码、角色、IP、设备 ID、地图名、错误文本或堆栈。阶段和结果只能来自枚举，耗时拒绝负数、NaN 和无穷值；小数点固定使用 invariant culture，便于日志采集端解析。登录和入图属于低频用户旅程，不在 Ping 或每帧路径写日志。

## 边界与后续

当前事件写入客户端既有日志渠道，不保证移动端日志一定上传或送达，不能据此宣称已有生产客户端 P95/P99。下一步应由选定的客户端日志/遥测后端采集这些固定事件，定义采样、离线缓存、同意与隐私政策，并在真实设备、弱网和公网环境建立基线。

`login` 包含路由、Realm、Gate 和登录完成事件的总时间，但不拆分动态服务器或账号标签；`enter_map` 包含场景切换完成，但“完成”仍由现有 `Wait_SceneChangeFinish` 语义决定，不等于美术资源全部稳定或首帧达到目标帧率。

回滚只需删除两个调用和固定格式辅助类，不改变协议、数据库或服务端判定。
